## Major changes

### M-1 — `DocumentProfile` gains `section_res`: a deterministic admission route

| Field | Content |
|---|---|
| **What changed** | `profile/base.py` — new `section_res` field; `hierarchy/unify.py` — new `declared_section_indices()`, `Candidate.declared`, provenance-aware scoring; `hierarchy/evidence.py` — new `W_SECTION_DECLARED = 0.8` |
| **Before → after** | An unlabelled, unstyled paragraph could become a section **only** via a referee confirming it (A-H.1). Now a profile may also declare its genre's headings by name, and a match is admitted with no referee |
| **Why** | Plan Cycle 3 deliverable 2. 125 of the genre's 127 documents carry `Relatório`/`Fundamentos`/`Conclusão`, and `is_prose_form_header` demands `upper_ratio >= 0.85` while these are title-case (~0.11). They were never proposed, so no referee was ever asked, and the documents were flat under **every** configuration |
| **Blast radius** | Every profile predating Cycle 3 declares `section_res=()`, so their trees are byte-identical — asserted by `test_a_profile_declaring_no_sections_is_unchanged`. Quoted and styled paragraphs are refused, mirroring `is_prose_form_header`'s own refusals |
| **Plan impact** | Recorded as **A-3.1**. The plan assumed profile data alone would suffice; it does not |
| **Confirmed** | Yes, explicitly, before implementation |

Invariant #8 is intact: this does not guess at structure, it reads a skeleton
the genre states in words. The weight matches `W_PROSE_HEADER_CONFIRMED`
deliberately — both say "this paragraph is a section", differing only in who
vouched, and a genre whose every document carries the same skeleton is at least
as good a witness as a model looking at one paragraph.

### M-2 — `build_tree` gains a `section_res` parameter

| Field | Content |
|---|---|
| **What changed** | `hierarchy/tree.py` — `build_tree(..., section_res=())`; `hierarchy/__init__.py` passes `profile.section_res` for the body and an explicit `()` for every annex |
| **Before → after** | A public signature gains one keyword-only parameter with an inert default |
| **Why** | M-1 needs the profile's declarations to reach tree building, and `build_tree` took no profile |
| **Blast radius** | Every caller outside `infer_hierarchy` passes nothing and is unaffected — `routing/viability.py`, `test_hierarchy_tree.py`, `test_render_generico.py` all unchanged and green |
| **Plan impact** | None beyond A-3.1 |
| **Confirmed** | Yes, explicitly, before implementation |

Annexes pass `()` **by intent, written at the call site**: an annex is a
different document travelling with this one, so a `Conclusão` inside it
concludes the annex, not the body.

## Minor changes

### m-1 — `servico`'s epigraph patterns are anchored

| Field | Content |
|---|---|
| **What changed** | `profile/servico.py` — `re.compile(r"carne-leao")` → `re.compile(r"^\s*carne-leao\b")` |
| **Before → after** | The bare pattern matched any line *mentioning* the carnê-leão. `sc_cosit_116_20190326` and `sc_cosit_14_20170116` — soluções de consulta about carnê-leão rendimentos — scored **0.9**, tying with `solucao_consulta`'s own epigraph match and winning on **registration order** alone |
| **Why** | A tie is a genre decided by a list literal, which `test_winning_margin` exists to forbid. Both documents emitted a `:servico:` URN type — a solução claiming to be a taxpayer service page |
| **Blast radius** | None to the sample: `CARNE_LEAO`'s first line is "Sistema de Recolhimento Mensal Obrigatório (Carnê-Leão)", matched at 0.9 by the *other* pattern. Verified: margin 0.85, profile unchanged. This is Cycle 2's m-6 lesson applied to `epigraph_res` instead of `authority_res` |
| **Plan impact** | None |

### m-2 — `jurisprudencia_generico`'s authority anchoring, **tried and reverted**

| Field | Content |
|---|---|
| **What changed** | `profile/jurisprudencia_generico.py` — anchored, then reverted to the original patterns, with the evidence recorded in the code |
| **Why reverted** | Three findings, in order of discovery: **(1) unnecessary** — the ten `sc_cosit` false positives score 0.40 through this branch with no epigraph match, and a solução now scores 0.9 on its own, so all ten are reclaimed either way (measured both ways: 125/127 identical); **(2) insufficient** — `sc_cosit_105` and `sc_cosit_72` open a line "O Superior Tribunal de Justiça (STJ), ao julgar…", which a line-anchored pattern still matches; **(3) not free** — `REsp_1306393` block 8 reads "Vistos, relatados e discutidos esses autos…" and matched only mid-line; dropping it moved `find_preamble`, which moved the front/body boundary 0–12 → 0–5 and lifted the body tree's confidence 0.0 → 0.3 |
| **How it was caught** | `test_measured_shape[REsp_1306393]`, which asserts `(sections, max_depth, flat, confidence)` **independently of the goldens**. The tree stayed `(0, 0, True, …)` — same sections, same depth, still flat — so every golden file was byte-identical and only the confidence moved. A golden-only check would have passed |
| **Plan impact** | Recorded as **A-3.2**, because it qualifies Cycle 2's m-6 |

The user approved anchoring (Q-3) on the understanding that it was the same
repair as m-6. It was not free, so it was reverted rather than absorbed, and the
approved *goal* — the twelve documents reclaimed — is met by the new profile
alone.
