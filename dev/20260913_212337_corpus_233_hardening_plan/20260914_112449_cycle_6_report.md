## 1. Summary

**Verdict: complete.**

Suite **6 167 passed / 0 failed / 4 skipped / 2 deselected**, up from 6 151 —
exactly the 16 new tests, with nothing displaced. **No `src/` file changed and no
golden moved.**

A refereed run over all 233 documents is now reproducible **offline, at zero
marginal cost, with zero network calls**, which is the cycle's exit criterion and
closes the dependency §1.8 warns about.

Four things are worth stating plainly.

**1. The evidence this cycle rests on was one `rm` away from being gone.** The
measuring run's 625 cached answers — every referee verdict plan §1.1 records —
were never in the repository. They survived only in a job scratch directory that
is deleted with the job, and this environment has no API key, so they could not
have been regenerated at any price. Publishing them was made the cycle's *first*
action, before the spec was written. Every number below depends on that copy
having happened.

**2. The plan's economic premise no longer holds, and the cause is our own
Cycle 3.** §1.8 argues the referee "earns its place" by moving flatness 115 →
107, eight documents gaining structure. The override table is exactly right and
reproduces to the number offline. But measured against Cycle 1's rules-only
baseline of 86, the referee now buys **three** documents, not eight: five of the
original eight were soluções de consulta that Cycle 3's `section_res` admits
**with no referee at all**. The referee did not get worse; the rules got better,
and the plan's case for referee spend was written before that happened.

**3. §5.3's question is answered "no", and the measurement is what decides it.**
The 74 `nao`→`secao` overrides look like a pattern begging to become a rule.
They are not: **35 of the 74 sit on texts that also appear as refusals** —
`RELATÓRIO` is confirmed 19× and refused 2×, `ORDEM DE INTIMAÇÃO` 7× / 1×, and
the bare roman numerals `I`/`II`/`III`/`IV` land on both sides. A text-keyed rule
would fabricate 19 sections to rescue 35, and a fabricated section is
indistinguishable from a real one in the output. The referee is reading position
and neighbours — what `next_ctx` was added for in A-H.2 — not applying a lookup
table we could copy.

**4. The ten cache misses are a feature, and that had to be proved rather than
assumed.** Replaying the corpus, 684 of 694 questions hit. The ten that miss are
all questions whose recorded answer was an **abstention**, which `api.py`
deliberately never caches ("a timeout is a fact about the network, not about the
question"). Each was checked individually: every one is `rule=nao → final=nao`,
so **no outcome depends on them**. Had even one changed a verdict, the published
set would not reproduce the run and the cycle's headline claim would be false.

0.2 ms/document is below the noise of reading the `.docx`.

## 7. Deviations and open items

- **The cycle changed no `src/` code**, so the usual regression signal (a moving
  golden) could not fire. The risk this creates is the opposite one — a test that
  passes vacuously — so every corpus assertion pins a *measured number* rather
  than a tautology, and the recording script's `--check` reproduces them through a
  separate code path.
- **The 50 `quoted`→`own` overrides were not analysed for rule-learnability.**
  Deliverable 3 asks only about the 74 `nao`→`secao`, and §1.8 singles those out.
  The other 50 are a real and untouched question: they are the referee correcting
  the *quotation* guard, not the heading gate, and they are worth their own
  measurement if referee spend is ever revisited.
- **The token figures are a floor, not a bill.** No provider invoice was
  available, and `meta.excerpt` truncation means the reconstructed prompts
  understate the real ones. A true cost figure needs either a provider usage
  export or a recording run with token accounting — neither possible here without
  an API key.
- **A live re-record was not performed.** `--check` verifies the committed answers
  answer today's questions; it cannot verify the model would *still give* those
  answers. That distinction is in the README, and re-recording needs
  `LEXML_REFEREE_API_KEY`, which this environment does not have.
