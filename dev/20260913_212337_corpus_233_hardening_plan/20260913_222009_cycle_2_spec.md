## 2. Measurement — what is actually wrong

Everything below was measured over the 234 emitted XMLs and the 233 sources in
this environment, not taken from the plan.

### 2.1 46 defective URNs, not 24

§1.3 counted `Metadata.missing` only. It did not count documents that silently
take a **profile default** for authority. Measured:

| Defect | Count |
|---|---|
| `authority` defaulted to `federal` by the `generic` profile | **27** |
| `date` sentinel `0000` | 17 |
| `number` sentinel `;0` | 10 |
| **Distinct documents affected** | **46** |

The 27 decompose as `solucao.consulta.cosit` 43 → of which the authority-default
subset, plus `solucao.divergencia.cosit` 3, `solucao.consulta.interna.cosit` 3,
`documento` 3, `ato.declaratorio` 2, `parecer` 1, `nota.pgfn` 1,
`resolucao.tse` 1. This is Finding C (§1.4) surfacing as a **URN defect**: the
URN claims the wrong issuer, which is worse than claiming none.

### 2.2 Some URNs are confidently *wrong*, not merely incomplete

A distinct and more serious class, found while measuring:

| Document | Emits | Should be | Cause |
|---|---|---|---|
| `nota_pgfn_crj_1114_2012` | `…:portaria:0000;294` | `…:nota:2012;1114` | read **a citation to another document** as its own identity |
| `nota_pgfn_crj_1104_2017` | `…:sumula:0000;1470720` | `…:nota:2017;1104` | same |
| `parecer_pgfn_crj_701_2016` | `…:sumula:0000;614406` | `…:parecer:2016;701` | same |
| `REsp_1306393` | `…:sumula:0000;1306393` | `…:acordao:…` | fixed `urn_type="sumula"` for an acórdão |

**Root cause, verified.** `_EPIGRAPH_RE`'s `tipo` group is
`[A-Za-zÀ-ÿ][A-Za-zÀ-ÿ\s\-]{2,60}?` — it admits letters, spaces and hyphens but
**not `/`**. So `NOTA PGFN/CRJ/Nº 1114/2012` does not match at paragraph 1, the
scan falls through, and paragraph 2's `Portaria PGFN Nº 294/2010.` — a citation
— matches instead. Measured directly:

```
NOTA PGFN/CRJ/Nº 1114/2012              plain=- path=-
Portaria PGFN Nº 294/2010. Parecer …    plain=Y  tipo='Portaria PGFN' num='294'
```

This is the single most valuable finding of the reconnaissance, because it means
these four documents **do** state their own identity and the parser was looking
past it. Fixing the regex recovers number *and* date from the document itself,
which is strictly better than any filename fallback.

### 2.3 Exactly one URN collision

229 distinct URNs across 234 files. The **only** collision is the six service
descriptions, all on `urn:lex:br:ministerio.fazenda;secretaria.receita.federal:servico:0000;0`.
The wider collision problem §1.5 worried about does not exist in this corpus.

### 2.4 Filename recoverability

205/233 filenames carry a parseable date, ~209/233 a number. But the four
documents of §2.2 are recoverable **from their own text** once the regex is
fixed, so filename recovery is needed for a smaller set than it first appeared.

### 2.5 The URN attribute is unconstrained by the schemas

`lexml-base.xsd:1055` types it `xsd:anyURI` — no pattern. A slug-valued number
component (`;dirf`) validates against both schemas. The only constraint is our
own `_NUMBER` regex, which is ours to widen.

### N-1 — Reconciling Q-2 and Q-3 (mine to settle, recorded not asked)

Q-2 sanctions a filename **outranking** a body read; Q-3 pins the filename at
**last resort**. Read together with their option text, the coherent rule is:

> The filename is last-resort by default (A-2.1 preserved). The **single
> exception** is a body-derived number that is detectably a citation to another
> document — then the filename wins.

I am implementing it as one rule with one narrow exception rather than two
competing chains. Because §2.2's regex fix removes the *cause* of the suspect
reads, the exception is expected to fire rarely; it is a safety net, not the
primary mechanism.

### N-2 — `solucao_consulta` authority without building the profile

The 27 authority defaults are mostly `sc_cosit`, whose epigraphs name their own
issuer (`Solução de Consulta Cosit nº 100`, `Disit/SRRF03`). Building a
`solucao_consulta` profile is **Cycle 3's** deliverable, so I will not build it.
I will add the sigla entries to the `generic` profile's `authority_map` (today
empty) so the authority resolves from the epigraph without a new profile. Cycle
3 can move them onto the profile it builds.

### N-3 — Not in scope

Cycle 2 does not touch hierarchy, flatness, or the referee. Deliverable 4
(cross-process collision safety) is addressed as a **documented statement**
rather than locking, per the plan's own "or an explicit statement" wording.

## 4. Expanded goals

### G-1 — Epigraph extraction admits path-form document types (§2.2)

`_EPIGRAPH_RE`'s `tipo` group admits `/` so `NOTA PGFN/CRJ/Nº 1114/2012` matches
at paragraph 1. Guarded so it cannot swallow a sentence: the `/` may not be
followed by whitespace, and the existing length bound stays.

Recovers 4 documents' number and date from their own text.

### G-3 — Filename-derived number, mirroring the existing date fallback

`_number_from_filename(filename)` beside `_date_from_filename`, wired as the
last link in a number chain, recording `number_source`. `Metadata` gains
`number_source: str | None`, carried through `to_dict`/`from_dict` exactly as
`date_source` is.

Applies only when the body yields nothing, **except** N-1's citation case.

### G-4 — A suspect-body-read guard (N-1)

`_number_looks_like_citation(epigraph_text, number)` — true when the matched
number sits inside a reference to another document rather than in the document's
own epigraph. When true and the filename offers a well-formed number, the
filename wins and `number_source="filename:corrected"`.

### G-5 — Slug URN component for the six service documents (Q-4, Q-5)

- `_NUMBER` in `urn.py` widens to accept a slug alternative alongside digits.
- `servico` profile gains a rule deriving the slug from the document's **own
  first paragraph** (`Declaração de Benefícios Fiscais — DBF` → `dbf`), not from
  its filename — each of the six states its name and acronym in paragraph 1.
- `CARNE_LEAO` → `…:servico:0000;carne.leao`.

**Major change (Q-5 confirmed):** moves `tests/golden/metadata/`,
`tests/golden/generico/`, `generico_aninhado/`, `segments/` for `CARNE_LEAO`.
Regenerated via `scripts/regen_goldens.py` as a reviewed diff.

### G-6 — `jurisprudencia_generico` derives doc_type from the epigraph (Q-6)

Single `urn_type="sumula"` → derived: `sumula`, `acordao`, `recurso.especial`,
`acao.direta.inconstitucionalidade`. Moves `tests/golden/metadata/REsp_1306393.json`.
The case number is **left as the number**, per Q-6.

### G-7 — Cross-process statement (deliverable 4)

`parse -o` is documented as single-invocation: `taken` is per-process, and two
concurrent `parse` runs targeting one directory may overwrite. Documented in the
`_write_bundle` docstring and the CLI help, with a test asserting the documented
behaviour rather than a lock.

## 8. Risks

- **Golden movement wider than confirmed.** G-5/G-6 move goldens by design; anything
  *else* moving means an unintended behaviour change. E-5 is the guard, and any
  extra movement is an escalation before regenerating. **Medium** — the highest
  risk in this cycle.
- **The epigraph regex over-matches.** Admitting `/` could let a sentence match.
  Bounded by the no-whitespace-after-slash guard and the existing length cap;
  `test_a_citation_is_not_read_as_identity` is the direct guard. Medium.
- **`authority_map` entries tuned on 233 documents** generalise worse than
  genre-agnostic evidence — the §10 warning. Mitigated by preferring epigraph
  evidence over profile defaults. Low.
- **A slug number breaks a downstream consumer** that assumes digits — notably
  the linker. A-L.9 pins `DEFAULT_CONTEXT_URN` as a constant and every caller
  passes it, so a document's own URN never reaches the linker as context. Low.
