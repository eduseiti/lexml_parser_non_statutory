## Summary

**One major change, confirmed with the user before implementation**, plus five
minor ones. The major is the only one that moves a delivered artifact: the 15
hierarchy goldens each gain two keys.

**The golden movement was proved additive rather than asserted.** Every one of
the 15 was compared against its `HEAD` version with the two new keys stripped

`flat`, no `sections`, no `rejected`, no `span` value moved anywhere.

## Major change

### M-1 — `DocSignals` gains `flat_cause` and `span_coverage`; the 15 hierarchy goldens move

| Field | Content |
|---|---|
| **What changed** | `hierarchy/evidence.py` — new `FLAT_CAUSES` vocabulary, new `DocSignals.flat_cause` and `DocSignals.span_coverage`, both serialized by `to_dict()` and restored by `from_dict()`; `tests/golden/hierarchy/*.json` — all 15 regenerated |
| **Before → after** | A flat tree said only `flat: true, confidence: 0.0`. Confidence `0.00` was doing double duty — emitted both when a document has no structure and when evidence fusion found no *candidate* — and the artifact did not separate them. Now every flat tree names its cause, and records what fraction of the document its body span covered |
| **Why** | Plan §1.2 and Cycle 1 deliverable 1. The plan's word for this is *silence*: "a downstream consumer cannot tell a document that genuinely has no internal structure from one whose structure was not recognised" |
| **Blast radius** | Exactly 15 files, all under `tests/golden/hierarchy/`. Measured **before** asking the user: no `generico`, `generico_aninhado`, `generico_linked`, `metadata`, `norma`, `norma_linked`, `routing`, `segment`, `segments` or `styled` golden embeds the tree dict, so none moves. 16 signal blocks now carry the keys — 15 bodies plus `port_mf_277`'s annex, the corpus's only annexed sample. The annex carries them at their **inert defaults** (`flat_cause=""`, `span_coverage=0.0`): its tree is not flat, and an annex never receives a coverage ratio. `test_golden_roundtrips` also failed pre-regeneration, for the ordinary reason that the committed file predated the keys |
| **Plan impact** | Recorded as **A-1.1**. §1.2's taxonomy proposal is corrected by **A-1.2** |
| **Confirmed** | Yes, explicitly, before implementation (Q-1), with the blast radius stated in the question rather than discovered afterwards |

The placement on `DocSignals` rather than `HierarchyTree` is evidence-backed,
not preference. `segments/roundtrip.py::_tree_from_segments` constructs
`HierarchyTree(sections=…, preamble=…)` with no `signals`, so it inherits the
default; and `test_segments_roundtrip.py`'s `tree.signals == DocSignals()`
assertion is written — by its own docstring — "against freshly constructed
defaults rather than against literals, so that adding a field to `Evidence` or
`DocSignals` extends this test automatically instead of leaving the new field
unchecked." A field with an inert default therefore **strengthens** that test.
It passed unchanged.

## Minor changes

### m-1 — `build_tree` computes the cause

| Field | Content |
|---|---|
| **What changed** | `hierarchy/tree.py` — new `_flat_cause()`; `build_tree` passes it into `DocSignals`; the `if not blocks:` early return now carries `flat_cause="empty_body_span"` |
| **Before → after** | The early return produced a flat tree with no cause, which reads as "no reason recorded" — wrong for `ad_srf_22` and `adn_cosit_19`, whose whole content is front and back matter |
| **Why** | Deliverable 1. The cause is derived from values `build_tree` had already computed; nothing feeds back, so no tree's shape depends on it |
| **Blast radius** | None to inference. `test_measured_shape` — the guard that caught Cycle 3's invisible defect — is green for all 15, and the goldens moved by added keys only |

### m-2 — `infer_hierarchy` computes `span_coverage`

| Field | Content |
|---|---|
| **What changed** | `hierarchy/__init__.py` — new `_with_span_coverage()`, applied to the body tree only |
| **Before → after** | Body trees now carry the ratio of body blocks to document blocks; annexes keep `0.0` |
| **Why** | **`build_tree` cannot compute this.** It receives an already-sliced span and never sees the blocks outside it, and `Span` carries `start`/`end` but no document total. `sc_cosit_100`'s declared headings at blocks 42 and 164 are simply not in scope there. `infer_hierarchy` holds both `doc.blocks` and `segmentation.body`, so it is the only place the ratio exists |
| **Blast radius** | Annexes assert `0.0` explicitly (`test_annexes_carry_no_span_coverage`) — an annex is a different document travelling with this one, the same reasoning that gives annexes `section_res=()`. A document with no blocks returns the tree untouched rather than dividing by zero |

### m-3 — `corpus.py` gains genre and flatness reporting

| Field | Content |
|---|---|
| **What changed** | New `genre_of()`; `DocumentOutcome` gains `flat_cause`, `span_coverage`, `genre`; `CorpusReport` gains `by_flat_cause()` and `by_genre_flatness()`; both reach `to_dict()`; `render_corpus_report` gains a "Flat because:" line and a "Flatness by genre:" section |
| **Why** | Deliverable 2 — "so `ad_pgfn` at 14/15 is visible as a pattern rather than as fifteen unrelated documents" |
| **Blast radius** | `by_flat_cause()` counts only flat documents, so it reconciles against the flat count and a structured document never appears as an empty-string bucket. `by_genre_flatness()` falls back to `genre_of(source)` when the field is unset, so an outcome built before the field existed still groups correctly. Ordering is flat-count descending then name — invariant #4 |
| **Note** | The genre axis is the **filename**, not the profile. `routing/genre.py` keys priors off the profile, which is right for routing and wrong here: `ad_pgfn` is not a profile — those documents select `ato_declaratorio`, which also serves genres that are not flat. Grouping by profile averages the signal away, which is what §1.2 says hid it |

### m-4 — `--format=json` and `dump-tree --why` surface the cause

| Field | Content |
|---|---|
| **What changed** | `cli.py::_parse_json` gains `flat_cause` and `span_coverage`; `hierarchy/__main__.py::_render_tree` prints a "flat because:" line on a flat tree |
| **Blast radius** | Additive. `test_parse_json_carries_the_run_report` asserts `key in report`, so a new key does not disturb it. The `--why` line appears only when the tree is flat *and* has a cause — verified against both a flat sample and a structured one |

### m-5 — two exact-key test assertions extended

| Field | Content |
|---|---|
| **What changed** | `tests/unit/test_corpus.py` — `test_to_dict_keys_are_stable` gains `by_flat_cause`/`by_genre_flatness`; `test_outcome_to_dict_keeps_every_field` gains `flat_cause`/`span_coverage`/`genre` |
| **Why** | Both are deliberate equality assertions over a pinned JSON surface. Noticing exactly this kind of change is their purpose |
| **Blast radius** | Test data, not assertions weakened: both remain exact equality over the full key set. Nothing was relaxed to a subset |

48 insertions, 16 deletions across the 15 files, where the deletions are the
trailing-comma reflow on the line the keys were appended after.

new keys stripped recursively, and the result compared against
`git show HEAD:<path>`. All 15 match. **Zero violations.**

No other golden kind moved. `git status --porcelain tests/golden/` reports
exactly 15 files.
