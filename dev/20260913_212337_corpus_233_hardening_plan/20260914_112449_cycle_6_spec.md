### Non-blocking decisions taken here

- **The measurement runs `build_model` per document**, not `run_corpus`.
  `run_corpus` builds its own `DecisionLog` internally and surfaces only the
  aggregated `DecisionsReport`; deliverable 3 needs the **raw records** (per-record
  `rule_verdict` / `referee_verdict` pairs), which only a caller-supplied log
  exposes. This is the same call chain `run_corpus` uses internally, so nothing
  drifts.
- **Validation and rendering are skipped in the measurement.** Neither can change
  a hierarchy decision, and both dominate the runtime. The wall-time figures in
  deliverable 2 are therefore explicitly *pipeline* times, and say so.
- **Test module name:** `tests/unit/test_referee_economics.py`, beside the five
  existing `test_referee_*.py` modules.
- **Recording script name:** `scripts/record_corpus_referee_fixtures.py`,
  mirroring `scripts/record_linker_fixtures.py` including its `--check` flag.
- **The deliverable-3 analysis goes to `docs/`**, per the plan's own wording for
  Cycle 6 ("the override analysis recorded in `docs/`") and following Cycle 1's
  `ad_pgfn` investigation precedent.

### Reconciliation findings — what the plan assumes vs. what is true

**R-1 — §1.8's headline figure is stale, and the cause is Cycle 3.**
§1.8 records the referee moving flatness **115 → 107**, eight documents gaining
structure. Measured today, post-Cycle-3, rules-only baseline 86:

| | §1.8 (pre-Cycle-3) | Measured 2026-09-14 |
|---|---|---|
| Flat, rules-only | 115 | **86** |
| Flat, refereed | 107 | **83** |
| Documents gaining structure | 8 | **3** |

The referee's *marginal* value has fallen because Cycle 3's `section_res` already
admits the `RELATÓRIO`/`FUNDAMENTOS`/`CONCLUSÃO` skeleton deterministically. Both
measurements are correct at their own commit; the plan does not say which commit
it measured, which is the same defect A-3.3 already recorded about §1.2.
**Amended as A-6.1** (Q-3).

**R-2 — the 127 overrides reproduce exactly, offline.**
§1.8's table (`nao`→`secao` 74, `quoted`→`own` 50, `continuation`→`boundary` 3,
across 53 documents) reproduces **to the number** from the published cache with
**zero network calls**. §1.8 is right about *what the referee did*; it is only its
flatness *consequence* that has moved.

**R-3 — deliverable 3's answer is "no", and the plan anticipates "maybe".**
§5.3 asks whether the 74 `nao`→`secao` overrides "can be captured as a rule".
Measured, they cannot — see §4, deliverable 3. This is a **negative finding**, the
same shape as Cycle 1's A-1.5 on `ad_pgfn`.

**R-4 — the cache was nearly lost.** The 233-run cache existed only in a job
scratch directory that is deleted with the job. It has been copied into the
repository as the first action of this cycle, before anything else.

## 3. Expanded goals

### Deliverable 1 — publish the corpus referee cache as a fixture set

**`tests/corpus_referee_fixtures/`** — 625 JSON entries, 247 KB apparent,
7 500 insertions, every one carrying `meta.model = "deepseek-v4-flash"` (the
current `api.DEFAULT_MODEL`, so no key is stale).

Consumed exactly as the existing seam is:

```python
CachedAPIReferee(cache=RefereeCache(CORPUS_FIXTURES, read_only=True),
                 api_key=None, transport=explodes())
```

Plus `tests/corpus_referee_fixtures/README.md`, documenting what is here, its
provenance (a **live** DeepSeek run — unlike the seven hand-authored entries in
`tests/referee_fixtures/`), and how to refresh it.

### Deliverable 2 — measure and record cost, wall time, and hit rate

Measured over all 233 documents (`build_model`, no validation, no rendering):

| Measure | Value |
|---|---|
| Cache hit rate | **98.6%** (684 hits / 694 consulted) |
| Second-run hit rate | **98.6%**, `DecisionsReport` byte-identical |
| Network calls, either run | **0** |
| Rules-only pipeline | 1.43 s (6.1 ms/doc) |
| Refereed pipeline, warm cache | 1.46 s (6.3 ms/doc) |
| Referee overhead, warm | **+0.03 s total, +0.2 ms/doc** |
| Prompt input, whole corpus | ≥195 k tokens (~623 k chars) |
| Completion output | ~37 k tokens (~119 k chars) |

The 10 non-hits are **abstentions**, which `api.py` deliberately never caches —
duplicate-text questions (`'I'`, `'RELATÓRIO'`, `'CÓPIA'`, `'Fl. 23 DF COSIT RFB'`).
Verified: every one is `rule=nao → final=nao`, `changed=False`. **No abstention
changes any outcome**, so the published set reproduces the run exactly.

The token figures are a **floor**: `meta.excerpt` is truncated to 200 chars, so
the reconstructed prompts are shorter than those actually sent. The predecessor
plan's §7.2 sizing ($1–3 for the corpus) is consistent with this and is not
contradicted; it is simply now measurable rather than estimated.

### Deliverable 3 — a recommendation on the 74 `nao`→`secao` overrides

**Recommendation: do not turn them into a rule.** Evidence:

- **35 of the 74 confirmations sit on texts that also appear as refusals.**
  `RELATÓRIO` is confirmed 19× and refused 2×; `ORDEM DE INTIMAÇÃO` 7× / 1×; the
  bare roman numerals `I`, `II`, `III`, `IV` appear on **both** sides. A rule
  keying on text alone would be wrong in both directions.
- **The 40 unambiguous confirmations are dominated by the skeleton Cycle 3
  already handles** — `FUNDAMENTOS` (17), `CONCLUSÃO` (8), `FUNDAMENTOS LEGAIS`,
  `EMENTA`. `section_res` admits these **without any referee**, which is why the
  flatness delta fell from 8 documents to 3.
- What remains is a long tail of genuinely document-specific headings
  (`ALIENAÇÃO`, `AUXÍLIO-CRECHE.`, `ACÓRDÃOS PARADIGMAS`, `VOTO VENCIDO EM PARTE`)
  — one occurrence each, no shared shape.

Recorded in `docs/<stamp>_referee_override_rule_analysis.md`.

## 7. Risks

- **The fixture set is 625 new files.** Mitigated: `tests/linker_fixtures/`
  already tracks 891; measured repo cost is 247 KB apparent / 554 KB packed for
  the entire repository. `test_bare_checkout.py` `copytree`s `tests/`, so its
  mirror grows by 625 small files — measured as immaterial against its ~7 s run.
- **A future prompt edit silently invalidates every key.** This is real and is
  exactly what happened at A-H.2. Mitigated by `--check` on the recording script
  and by `test_the_cache_answers_almost_every_question`, which fails loudly if the
  hit rate collapses.
- **The cycle changes no `src/` code**, so the usual regression signal (goldens)
  cannot move. The risk is the opposite one: a test that passes vacuously. Every
  corpus assertion therefore pins a *measured number*, not a tautology.
