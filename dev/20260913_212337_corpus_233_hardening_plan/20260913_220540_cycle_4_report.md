## 1. Summary

**Verdict: complete.**

The suite is **fully green for the first time since `ac7103f`: 6 028 passed, 4
skipped, 2 deselected, 0 failed**, in 59.87s. The three
`tests/regression/test_bare_checkout.py` failures the plan records in §1.7 are
repaired, and they are repaired **beneath** the assertions rather than by
changing them — all three still assert exactly what Cycle 9 wrote them to
assert.

The fix is one file, 137 insertions and 5 deletions, nothing under `src/`, and
no golden moved.

Two things are worth stating plainly:

1. **The tests were right and the harness was wrong.** The bare checkout has
   been healthy throughout — 509 passed, 131 skipped, exit 0, on every run
   including the failing ones. What was broken was this module's reading of that
   result. A reader of the red suite would reasonably have concluded the parser
   had acquired a dependency on the unreleased schemas; it never had.

2. **Both broken parsers failed *falsily*, and that is the real defect.**
   `_count` returned `0` and the skip filter returned `[]` — neither raised. One
   assertion therefore announced `nothing ran in the bare checkout` about a run
   that had just passed 509 tests. Had the neighbouring assertions been phrased
   in the other direction ("no more than N skips"), the same broken parser would
   have read as **success**. The cycle's second deliverable exists precisely
   because a silent zero is more dangerous than a crash, and it is now pinned.

## 2. What was built

One file modified: `tests/regression/test_bare_checkout.py`. No subagents were
used — the cycle touches a single file, which the `dev-cycle` skill's own
"don't fan out trivia" rule puts below the fan-out threshold.

### The repair

| Change | Detail |
|---|---|
| `_run_pytest` | `--color=no` inserted into the subprocess argv, inside the function so no caller can forget it |
| `_strip_ansi(text)` *(new)* | Module-level helper over `_ANSI = re.compile(r"\x1b\[[0-9;]*m")` |
| `_count` | Strips ANSI before tokenising — `'\x1b[1m509'` no longer defeats `int()` |
| Two skip filters | Match `startswith("SKIPPED")` against a colour-stripped line |

### The guard (Cycle 4's second deliverable)

New module section `1b. the harness's own parsing`, four tests:

| Test | What it pins |
|---|---|
| `test_count_reads_a_colourised_summary` | The **verbatim** string from the `ac7103f` failure → 509 / 131. The exact §1.7 root cause, frozen as a regression |
| `test_count_reads_a_plain_summary` | `"128 passed, 4 skipped in 7.12s"` → 128 / 4 — stripping changed nothing for uncoloured input |
| `test_count_is_absent_safe` | An absent word still reads `0`, not an exception (pre-existing contract) |
| `test_the_harness_parses_its_own_subprocess_output` | On the **live** `bare_run`: a non-zero total parsed *and* non-empty skip lines, with a message that names the harness as the suspect rather than the bare checkout |

The last is the one that catches a future pytest output-format change, which no
fixed test string can anticipate.

### Accounting for the totals

The spec predicted 6 025 and the suite reports 6 028. The prediction was wrong,
and the arithmetic is worth recording rather than glossing:

| Measure | `ac7103f` | After | Δ |
|---|---|---|---|
| Module tests collected | 11 | 15 | **+4** |
| Suite collected (excl. 2 deselected) | 6 028 | 6 032 | **+4** |
| Suite **reported passed** | 6 021 | 6 028 | +7 |

The +4 is this cycle's four new tests, confirmed at collection time on both
sides. The reported-passed figure moves by 7 because at `ac7103f` three tests
failed and four more never reported a result at all — `bare_run` is
module-scoped, so the failures cost their neighbours too. 6 021 + 3 failed + 4
unreported = 6 028 collected, which reconciles exactly.
