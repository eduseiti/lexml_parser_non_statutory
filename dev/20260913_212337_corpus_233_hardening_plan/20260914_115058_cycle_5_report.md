## 1. Summary

**Verdict: complete.** This plan is now fully executed — all six cycles.

Suite **6 188 passed / 0 failed / 4 skipped / 2 deselected** in 84.33 s, up from
6 167: exactly the 21 new tests, nothing displaced. **No golden moved**, and the
whole `src/` diff is 11 inserted lines inside a docstring.

Four things are worth stating plainly.

**1. The guard §1.6 describes had never been exercised by a batch, and the
nearest existing test could not have caught the defect it guards.**
`test_robustness.py::test_one_bad_file_does_not_abandon_the_good_ones` runs
three documents with `--format=json` and **no `-o`**, counting `"urn"`
occurrences in stdout. But §1.5's defect wrote **229 files for 233 sources while
reporting success for all 233** — stdout was never the thing that was wrong. The
assertion that catches it is the *written-file count*, and nothing in the suite
made it until now.

**2. Every malformed file in the fixture set fails in the one place that was
already safe.** `corrupt`, `truncated`, `not_a_docx` and a zero-byte file all
fail inside `_read` — and `_read` was isolated *before* the measuring run's fix.
So a batch of malformed files, however large, cannot distinguish the repaired
`_cmd_parse` from the broken one. The §1.6 gap lived in model building,
rendering and validation, which no malformed file ever reaches. That is why
`test_a_failure_after_read_is_isolated_at_batch_scale` injects the failure into
`_render` instead, and asserts the **written count** (`GOOD - 1`) rather than
just the exit code: a removed guard changes how many files land, and an
exit-code-only assertion would not notice.

**3. The plan's "safe and cheap" is half true, and the report says which half.**
Measured before the spec was written: a re-run is byte-identical, count-stable,
and does not accumulate disambiguation suffixes across three runs — so **safe**
holds and is now pinned by three tests. **Cheap does not**: nothing is skipped,
every document is re-rendered. Rather than quietly omit the failing half,
`test_a_rerun_re_renders_rather_than_skipping` *asserts the absence of the
optimisation* — 20 renders after one run, 40 after two — so if a later cycle
implements skip-on-existing, that test is what must change, and having to change
it is the signal that the documented contract moved.

**4. A vacuous assertion was written, found and fixed inside the cycle that
named the risk.** The spec's §7 flagged "a test that passes vacuously" as this
cycle's main risk, since a cycle changing no behaviour has no golden to move.
The first draft of `test_an_all_bad_batch_writes_nothing_and_exits_one` contained
`assert x == [] if out_dir.exists() else True` — a conditional *expression* that
evaluates `True` whenever the directory is absent, which is the common case in
that very test. It was passing without testing anything. Fixed, and then
**proved to bite**: injecting a spurious file makes it fail with its own
message, and restoring makes it pass.

## 6. Plan updates

One amendment, **A-5.1**: the plan's "a batch of 200 with 5 bad documents writes
195 files" is read as illustrative of the shape rather than as a required
cardinality, and the tests use 20 + 5. The property is scale-independent and the
suite's 81-second budget is worth keeping.

because neither contradicts the plan — they record that the plan asked for
things that already existed (the fixtures) or that were deliberately scoped
(the "cheap" half of resumability).

## 7. Deviations and open items

- **"Cheap" resumability is not implemented**, by decision (Q-2). It is
  documented as absent and *pinned* as absent. `docs/20260914_115058_batch_resumability.md`
  §"Why it was left this way" records why the two easy implementations
  (skip-if-exists, skip-if-newer) are both wrong, and what a correct one would
  cost. This is the one open item a future cycle could pick up.
- **No new fixture builders**, by decision (Q-1). If a future cycle needs a
  degenerate shape the current set lacks, `degenerate.py` is the place.
- **Cross-process collision safety remains documented rather than locked** —
  Cycle 2's decision, unchanged here. Two concurrent `parse` runs into one
  directory can still overwrite each other. This cycle's re-run tests are all
  sequential and make no claim about concurrency.
- **The 233-document corpus was not re-run.** This cycle changes no behaviour,
  so there is nothing for a corpus run to measure that Cycle 6's run did not
  already establish.
