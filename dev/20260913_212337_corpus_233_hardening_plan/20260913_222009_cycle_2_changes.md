# Cycle 2 — changes to existing features

- **Cycle:** 2, corpus-233 hardening plan §1.3, §1.5, §2 Cycle 2
- **Date:** 2026-09-13
- **Spec:** [`20260913_222009_cycle_2_spec.md`](20260913_222009_cycle_2_spec.md)
- **Report:** [`20260913_222009_cycle_2_report.md`](20260913_222009_cycle_2_report.md)

## Summary

**Three major changes, all confirmed with the user before implementation**, plus
six minor ones. Unlike Cycle 4, this cycle deliberately changes delivered
behaviour: it is a URN-correctness cycle, and a URN correction *is* an output
change.

Every major was escalated at the moment it surfaced, not retrofitted.

## Major changes

### M-1 — The URN grammar admits a slug where a number goes

| Field | Content |
|---|---|
| **What changed** | `src/lexml_nonstat/model/urn.py` — `_NUMBER` |
| **Before → after** | `[0-9]+(?:-[0-9]+)?` → same, **or** a lowercase dotted slug (`[a-z][a-z0-9]*(?:[.-][a-z0-9]+)*`) |
| **Why** | Plan §5.1 / Q-4. Six service descriptions state no number or date in any form, so A-2.3's sentinels collapsed all six onto one URN — the corpus's only URN collision |
| **Blast radius** | The grammar widens, so nothing previously valid becomes invalid. Sentinel `0000;0` round-trips unchanged; digits and the `93-1` complement unaffected. A slug must start with a letter, so it can never collide with the `;0` sentinel |
| **Plan impact** | §5.1 answered; recorded as A-2.1 in the plan's amendment log |
| **Confirmed** | Q-4, then Q-5 for the golden movement |

### M-2 — An existing regression test's assertion was inverted

| Field | Content |
|---|---|
| **What changed** | `tests/unit/test_urn.py::test_is_valid_urn_negatives` |
| **Before → after** | The case `("non-numeric number", "…;abc")` asserted **invalid**. Removed, and replaced with three cases that stay invalid: `;12ab` (digits fused to letters), `;DBF` (uppercase), `;1dbf` (leading digit). Two positive tests added pinning the slug contract and the surviving sentinel |
| **Why** | M-1 makes `;abc` and `;carne.leao` the same shape; they cannot be told apart on shape alone |
| **Blast radius** | `test_urn.py` 96 → 100 tests, all passing. The module is **not weakened**: it gains two contracts and nets +2 negative cases |
| **Plan impact** | A-2.3 amended in reach, not repealed |
| **Confirmed** | Explicitly (Q-7), as the dev-cycle rules require for weakening a regression test |

### M-3 — `jurisprudencia_generico` derives its URN type per document

| Field | Content |
|---|---|
| **What changed** | `profile/base.py` gains `urn_type_res` + `urn_type_for()`; `profile/jurisprudencia_generico.py` declares eight patterns; `metadata.py` calls `prof.urn_type_for(epi_text)` |
| **Before → after** | One profile, one fixed `urn_type="sumula"` → the type is read off the epigraph. `REsp_1306393`: `…:sumula:0000;1306393` → `…:recurso.especial:0000;1306393` |
| **Why** | Q-6: an acórdão is not a súmula, and the profile serves four document kinds |
| **Blast radius** | Profiles declaring no `urn_type_res` behave exactly as before — verified: 13 of 15 samples' URNs are byte-identical. Moves `REsp_1306393` in 5 golden kinds |
| **Plan impact** | A defect the plan never scoped; recorded as A-2.2 |
| **Confirmed** | Q-6 |

## Minor changes

### m-1 — `Metadata` gains `number_source`

| Field | Content |
|---|---|
| **What changed** | `model/metadata.py` — new field, carried through `to_dict`/`from_dict` |
| **Before → after** | Provenance existed for date and authority but not number |
| **Why** | Plan deliverable 2: "recorded with its own `*_source` provenance value so a filename-derived component is never mistaken for a document-derived one" |
| **Blast radius** | Additive. It is why **13 metadata goldens move while their URNs do not** — measured field-by-field before regenerating, and the only changed key on those 13 |
| **Plan impact** | None |

### m-2 — The epigraph regex admits `/` in the document type

| Field | Content |
|---|---|
| **What changed** | `model/metadata.py` — `_EPIGRAPH_RE`'s `tipo` group |
| **Before → after** | `NOTA PGFN/CRJ/Nº 1114/2012` did not match at all; the scan fell through and read paragraph 2's **citation of another act** as the document's identity |
| **Why** | §2.2: four documents emitted a confidently *wrong* URN — worse than a sentinel, because nothing flags it |
| **Blast radius** | Recovers number and date from the documents' own text. No sample's URN moved. The slash may not be followed by whitespace, so a sentence cannot widen into a type |
| **Plan impact** | A defect class the plan did not name; recorded as A-2.3 |

### m-3 — A filename-derived number, and a citation guard

| Field | Content |
|---|---|
| **What changed** | `model/metadata.py` — `_number_from_filename`, `_number_looks_like_citation`, and a number chain in `extract_metadata` |
| **Before → after** | Number came from the epigraph or not at all → epigraph, then filename |
| **Why** | Plan deliverable 2; Q-3 |
| **Blast radius** | A-2.1's rank is preserved: the filename never pre-empts a body number, with the single exception Q-2 sanctioned (a body number that is detectably a citation). No sample's number moved |
| **Plan impact** | §5.2 answered |

**A bug in this helper was caught by its own test, after the first golden
regeneration.** The first draft accepted only a trailing ``_YYYYMMDD``, so
``parecer_pgfn_crj_701_2016`` and the three other ``_YYYY``-shaped names
returned ``None`` and the helper was near-inert for that shape. The corpus
numbers it appeared to recover were in fact recovered by m-2's epigraph fix
alone. `test_a_four_digit_year_is_not_a_number` failed, which is how it was
found; the regex now accepts ``\d{8}|\d{4}``. Goldens were re-generated
afterwards and did **not** move again (still 23 files), because no *sample*
carries a bare-year filename.
