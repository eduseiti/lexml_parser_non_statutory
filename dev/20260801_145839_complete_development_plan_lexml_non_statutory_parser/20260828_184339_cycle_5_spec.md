## 2. Schema facts measured before writing a line

Probed against **both** shipped schemas (`lexml-br-rigido.xsd`, `lexml09-flexivel.xsd`); every
row below is an executed validation, not a reading of the XSD.

| Encoding | Verdict | Consequence for the emitter |
|---|---|---|
| `PartePrincipal` = `choice(AgrupamentoHierarquico \| containerElements \| blockElements)+` | — | `p`, `ol`, `table` and `Agrupamento` are freely mixed siblings |
| `<p>` then `<Agrupamento>` under `PartePrincipal` | **valid** | body preamble may precede the sections |
| `Agrupamento` with `Bloco rotulo/nomeAgrupador/nivel` + `p` | **valid** | §5.1's shape is emittable verbatim |
| `Agrupamento` carrying **only** `Bloco`s | **valid** | a section with no own prose still emits legally |
| `Agrupamento` **empty** | **INVALID** (`blocksreq` is `minOccurs="1"`) | always emit `Bloco nome="nivel"`, which makes emptiness impossible |
| `Agrupamento` with no `id` | **INVALID** (`corereq`) | every `Agrupamento` gets an id |
| nested `ol`/`li`/`ol` inside `Agrupamento` | **valid** | lists need no flattening (§2.2) |
| `<table>` with no `id` | **INVALID** (`idreq`) | **tables need ids** — `pp1_tabN` / `anexoN_tabM` (§2.9) |
| `<td><p>` | **INVALID** | cells are inline-only (§2.2), as `Table.rows` already models |
| `<a href="…">` | **INVALID** | `link` is `xlink:href`, **required** — the document declares the xlink namespace |
| `<a xlink:href="…">` | **valid** | how Cycle 1's `Inline.href` is rendered |
| `<p class="quote">` | **valid** | how `Para.kind` survives into the XML |
| `<ol id="…">` | **INVALID** | `ol`/`ul` take no attributes at all |
| id beginning with a digit | **INVALID** (`xsd:ID` is an NCName) | id tokens always start with a letter |
| duplicate id | **INVALID** (`xsd:ID`) | uniqueness is enforced by the schema *and* by us |
| `Anexos` / `ReferenciaAnexo AlvoURN` in `DocumentoGenerico` | **valid** | the §2.9 pointer |
| `<Anexo><DocumentoGenerico>` as a sibling `LexML` document | **valid** | the §2.9 annex document |

### 3.2 Reconciliation finding — **the 40-block conservation hole** (blocking, resolved)

Measuring what Cycle 3's `render_front_generico` / `render_back_generico` actually emit against
every non-empty source block, over all 15 samples:

| Sample | blocks emitted by no renderer | where |
|---|---|---|
| `parecer_93_2018_decor_cgu_agu` | 21 | 7 front, 14 back |
| `pn_cst_38_19801031` | 7 | between its two signature blocks |
| `REsp_1306393` | 7 | front |
| `par_cosit_26_20000629` | 3 | 1 front, 2 back |
| `adn_cst_10_19910417` | 1 | front |
| `port_mf_454_19770825` | 1 | back |
| **total** | **40** | |

The cause is precise and is not a Cycle 3 defect: Cycle 3's `FrontMatter.span` / `BackMatter.span`
are the **contiguous hulls** (A-3.5), deliberately, so that the parts partition the document —
but `render_front_generico` / `render_back_generico` render the *named parts only*. The blocks
between the parts (`parecer_93`'s portal stamp and institutional banner, its `NUP:` /
`INTERESSADOS:` lines; `pn_cst_38`'s `De acordo` and `Publique-se` between two signatures;
`par_cosit_26`'s `Nota Normas:` disclaimer) are inside the hull, hence inside the segmentation,
and outside every rendered element.

A whole-document emitter that renders parts loses those 40 blocks and **fails invariant #2**.

**Resolution (spec decision D-6).** This cycle renders **regions, not parts**: `render/common.py`
gains `front_region()` and `back_region()`, which walk each hull in document order, emit each
named part as the same `Agrupamento` Cycle 3 emits, and emit each maximal run of unclaimed
non-empty blocks as `Agrupamento nome="preliminar"` (front) / `nome="nota"` (back).
Cycle 3's two functions are **left exactly as delivered** — no signature, no output change — and
their `_agrupamento` primitive is promoted to a public `agrupamento_block()` so there is one
implementation of the element shape, not two (the A-3.4 rule). This becomes plan amendment
**A-5.1**.

### 3.3 Non-blocking decisions taken here

| ID | Decision | Reason |
|---|---|---|
| D-1 | Section ids continue the front matter's ordinal sequence: front takes `pp1_agr1…agr{k}`, sections start at `pp1_agr{k+1}`, back matter keeps Cycle 3's distinct `pp1_agrf{n}` token | Cycle 3 already emits `pp1_agr{n}` for front parts; a separate token for sections would collide or would need a Cycle 3 change. Continuing the sequence needs **no change to Cycle 3** and keeps Rule A intact (`pp1_agr7_agr1`'s proper prefix `pp1_agr7` exists) |
| D-2 | `HierarchyTree.preamble` is wrapped in one `<Agrupamento nome="texto">` rather than emitted as bare `<p>` under `PartePrincipal` | every content node then sits in a citable, id-bearing container, which is what §2.4's segmentation consumes; and it matches §5.2's `nome="texto"` prose leaf, so cross-emitter segment URNs (invariant #11) line up in Cycle 5b. Not fabricated hierarchy — a flat container, honestly named |
| D-3 | `DocumentModel` gets **no** `to_json` / golden of its own | its five components already have byte-stable goldens; a sixth would duplicate them and make one behaviour change diff twice |
| D-4 | Table ids are a single document-wide counter, `pp1_tab1…` in the primary and `anexo1_tab1…` in an annex | §2.9's reference convention verbatim |
| D-5 | The annex marker paragraph (`ANEXO ÚNICO`) is emitted as `Agrupamento nome="tituloAnexo"` at the head of the annex document | Cycle 4 deliberately excludes it from the annex tree (`build_tree(span_blocks(annex.span)[1:])`), so the emitter is the only place it can be conserved |
| D-6 | Regions, not parts — see §3.2 | conservation |
| D-7 | `Section.kind` is `Agrupamento/@nome` verbatim; `Bloco nome="nivel"` is `str(Section.level)` | §5.1; `nome` is a free-form `xsd:string`, and `SECTION_KINDS` is already the ratified vocabulary |
| D-8 | New tests split across `tests/unit/`, `tests/golden/` and a new `tests/regression/` | plan §9.1 names `tests/regression/` for conservation, round-trip and cross-emitter; this cycle creates it |

### 4.4 `src/lexml_nonstat/render/generico.py` *(new)*

```python
@dataclass(frozen=True)
class RenderedDocument:
    primary: etree._Element                  # <LexML>
    annexes: tuple[etree._Element, ...] = () # one <LexML><Anexo> per annex

```

Primary shape:

```xml
<LexML xmlns="http://www.lexml.gov.br/1.0" xmlns:xlink="http://www.w3.org/1999/xlink">
  <Metadado>…</Metadado>                                   <!-- Metadata.to_xml() -->
  <DocumentoGenerico>
    <PartePrincipal id="pp1">
      <Agrupamento id="pp1_agr1" nome="epigrafe">…</Agrupamento>       <!-- front region, doc order -->
      <Agrupamento id="pp1_agr2" nome="preliminar">…</Agrupamento>     <!-- residue run (D-6) -->
      <Agrupamento id="pp1_agr5" nome="texto">…</Agrupamento>          <!-- body preamble (D-2) -->
      <Agrupamento id="pp1_agr6" nome="secao">                          <!-- sections, flattened -->
        <Bloco nome="rotulo">2.</Bloco>
        <Bloco nome="nomeAgrupador">DAS SOCIEDADES COOPERATIVAS</Bloco>
        <Bloco nome="nivel">1</Bloco>
        <p>Texto introdutório.</p>
      </Agrupamento>
      <Agrupamento id="pp1_agr6_agr1" nome="subsecao">…</Agrupamento>  <!-- sibling, path id -->
      <Agrupamento id="pp1_agrf1" nome="assinatura">…</Agrupamento>    <!-- back region -->
    </PartePrincipal>
    <Anexos><ReferenciaAnexo AlvoURN="urn:…;277!anexo1"/></Anexos>
  </DocumentoGenerico>
</LexML>
```

Annex document shape (§2.9):

```xml
<LexML …>
  <Metadado><Identificacao URN="urn:…;277!anexo1"/></Metadado>
  <Anexo>
    <DocumentoGenerico>
      <PartePrincipal id="anexo1_pp">
        <Agrupamento id="anexo1_pp_agr1" nome="tituloAnexo"><p>ANEXO ÚNICO</p></Agrupamento>
        …sections, ids anexo1_pp_agr2…, tables anexo1_tab1…
      </PartePrincipal>
    </DocumentoGenerico>
  </Anexo>
</LexML>
```

Sections are emitted **depth-first, pre-order, as siblings** — the flattening §5.1 requires — each
carrying `Bloco nome="rotulo"` (when `Section.label`), `nomeAgrupador` (when `Section.heading`) and
always `nivel`; then its own body nodes. Descendants follow as siblings with path-composed ids.

## 8. Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| The 40-block hole is wider than measured on unseen documents | medium | conservation is asserted as **arithmetic over regions**, not over an enumerated list of part names — an unclaimed run is rendered by construction, whatever it contains |
| `xsd:ID` collisions between region ids and section ids | low | one `IdAllocator` issues every id in a document and refuses a duplicate; the schema's own `xsd:ID` check is a second, independent net (E3) |
| Rule A silently broken by a future emitter change | medium | `missing_prefixes()` is a public checker with a **positive** test (a deliberately gapped id set must be reported), so the checker itself cannot rot into a no-op |
| Whitespace normalisation makes conservation compare unequal for cosmetic reasons | high | compare `" ".join(text.split())`-normalised strings, and report the symmetric difference in the assertion message rather than a bare count |
| `regen_goldens.py`'s `KINDS` refactor silently rewrites the five existing golden kinds | low | the five existing golden test modules are the guard; run them before regenerating anything |
| The flat rendering of `port_mf_277` pre-empts a Cycle 6 decision | low | it is the documented §3 fallback and is labelled as such; Cycle 6 emits `norma` for it and keeps this golden as the fallback evidence |
