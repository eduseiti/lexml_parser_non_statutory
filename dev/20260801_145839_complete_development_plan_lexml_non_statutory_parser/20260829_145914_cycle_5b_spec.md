## 2. Reconciliation outcomes

### Blocking questions asked, and the user's answers

**R-1 — the baseline is red by one test, environmentally.**
`tests/unit/test_referee_api.py::test_httpx_is_not_imported` asserts
`"httpx" not in sys.modules`. It fails at *collection* time, before any of our
code runs: the `langsmith` pytest plugin, auto-loaded from a `pytest11` entry
point in this conda environment, does `import httpx` at plugin-load. Traced to
`site-packages/langsmith/utils.py:38`. Our package is clean — a `builtins.__import__`
trace over `import lexml_nonstat.referee.api` shows no `httpx`, and
`PYTEST_DISABLE_PLUGIN_AUTOLOAD=1 pytest tests/unit/test_referee_api.py` is
81 passed.

> **Answer: harden the test.** Rewrite the assertion to check what it actually
> means — that exercising *our* package does not **add** `httpx` to
> `sys.modules`. Snapshot presence before, assert unchanged after. Immune to
> third-party plugins, still kills a module-level import in our own code.
> Logged as a Cycle 5b change to an existing test (**C-1**).

**R-2 — what does `render_generico_aninhado` do when the schemas are flat?**
§5.2 says the emitter "refuses with the probe's diagnostic when the vendored
schemas are flat", but `lexml/` — the *shipped* generation and the default
everywhere — **is** flat. Read literally, the emitter would refuse on every
default checkout, including inside its own tests.

> **Answer: always render; validation is what is gated.** The renderer is a
> pure function and always produces the nested tree. Only *emitter selection*
> (the CLI, Cycle 8) consults the probe and refuses. Tests validate against
> `lexml-proposed/` and **skip with a reason** when the probe reports flat —
> which is exactly how the cycle's own test bullet words it.

**R-3 — when is `<Bloco nome="ordem">` emitted?**
The cycle bullet says "for unlabelled sections"; §5.4 says the reader "uses
`Rotulo` or a recorded source index".

> **Answer: always, on every `AH` and every prose leaf.** One uniform rule, so
> the reader never needs a second code path and never has to sort `Rotulo`
> strings (which are not reliably sortable — `2.`, `2.1`, `IV`, `a)`). The
> marker is invisible to text extraction, exactly like `vazio`.

**R-4 — golden scope: the cycle says 14, Cycle 5 emitted 16 documents.**

> **Answer: all 15 samples + the annex = 16 nested goldens**, mirroring Cycle 5
> (**A-5.5**'s precedent). This makes cross-emitter equivalence checkable
> file-for-file over the whole bundle. The **exit criterion still names the 14**
> `generico`-routed samples.

### Non-blocking decisions taken myself

- **D-1 — module name and surface.** `src/lexml_nonstat/render/generico_aninhado.py`,

  elements*, produced by the same shared functions; only the body differs

## 3. The measured content model

§5.4 says the constraints are "measured against `lexml-proposed/`, not assumed".
I measured them, 24 cases, before writing a line of the emitter. The effective
content model is:

```
AgrupamentoHierarquico[@id required][@nome required] ::=
    Rotulo?  NomeAgrupador?  AgrupamentoHierarquico*  (Agrupamento | Bloco | LXhierCompleto)+
```

| # | Probe | Result | Consequence |
|---|---|---|---|
| A | subsections **before** own prose | **valid** | Constraint 1 confirmed |
| B | own prose **before** subsections (natural reading order) | **invalid** — "element is not expected" | Constraint 1 is real; the emitter must reorder |
| C | `<Bloco nome="vazio"/>` as the only non-`AH` child | **valid** | Constraint 2's resolution confirmed |
| D | `AH` with subsections but **no** non-`AH` child | **invalid** — "Missing child element(s)" | Constraint 2 is real |
| E | bare `<p>` under `AH` | **invalid** | Constraint 3 confirmed; §2.1 row E still fails, correctly |
| **K** | **`<Bloco>` *before* a nested `AH`** | **invalid** | **new finding — see below** |
| N | `Bloco` after subsections, before prose | valid | where `ordem` goes |
| J | `NomeAgrupador` before `Rotulo` | invalid | the two natives are ordered |
| Q/R/S | `Rotulo` only / `NomeAgrupador` only / neither | all valid | both natives are genuinely optional |
| T/U | `AH` without `@nome` / without `@id` | both invalid | both attributes required |
| V | `vazio` alongside subsections **and** prose | valid | `vazio` is legal but redundant there — emit only when needed |
| W | empty `<Agrupamento/>` | invalid | `blocksreq`; why `vazio` is a `Bloco` and not an `Agrupamento` |
| X | `AH` nested inside a flat `Agrupamento` | invalid | the two emitters' shapes do not mix inside the body |
| H/I | flat `Agrupamento` as a **sibling** of `AH` under `PartePrincipal` | valid | front/back regions coexist with a nested body ✔ |
| G/L | table / nested `ol`-`ul` inside a prose `Agrupamento` | valid | content rendering reused unchanged |
| M | `AH` nested four deep | valid | `pn_cst_38`'s depth is expressible |

**New finding, beyond the plan (candidate amendment A-5b.1).** Probe **K**
shows the extension `choice` follows `AgrupamentoHierarquico*` for **`Bloco`
too**, not only for `Agrupamento`. So a parent's own `ordem` marker cannot
precede its subsections either — it must be emitted *after* all of them,
alongside the prose leaf. §5.4's Constraint 1 is stated in terms of "own
prose"; it is in fact **every non-`AH` child**. The emitter's canonical order
is therefore:

```
Rotulo?  NomeAgrupador?  AH*  Bloco[@nome="ordem"]  (Agrupamento[@nome="texto"] | Bloco[@nome="vazio"])
```

## 4. Expanded goals

### 4.1 `src/lexml_nonstat/render/generico_aninhado.py` (new)

```python
render_generico_aninhado(model: DocumentModel) -> RenderedDocument
render_generico_aninhado_from_docx(path, *, filename: str | None = None) -> RenderedDocument
```

Both return `RenderedDocument` with `emitter="generico-aninhado"`. Never raises
on a real document (Cycle 5's contract: an empty body, absent front matter and
absent back matter are all ordinary in this corpus).

**Per `Section`, emitted in this canonical order:**

1. `<Rotulo>` — iff `section.label`; **native**, not `<Bloco nome="rotulo">`
2. `<NomeAgrupador>` — iff `section.heading`; **native**
3. every child `Section`, recursively, in document order
4. `<Bloco nome="ordem">{index}</Bloco>` — D-5's 0-based document-order index
5. **either** `<Agrupamento id nome="texto">` holding the section's own
   `body` nodes, **or** `<Bloco nome="vazio"/>` when the section has no
   renderable own prose (Constraint 2)

`AgrupamentoHierarquico` carries `id` (path-composed, token `agh`) and
`nome` (the `Section.kind`, from the ratified `SECTION_KINDS`).

**Explicitly not emitted:** `<Bloco nome="rotulo">`, `<Bloco nome="nomeAgrupador">`,
`<Bloco nome="nivel">`. Depth is `count(ancestor::AgrupamentoHierarquico)`.

**Unchanged from Cycle 5:** the `Metadado`, the `PartePrincipal id="pp1"`,
front and back regions via `front_region()`/`back_region()` (A-5.1), the body
preamble as `Agrupamento nome="texto"` (A-5.7), annexes as standalone sibling
`<LexML><Anexo>` documents with `anexoN_pp` / `anexoN_tabM` / `!anexoN`
(§2.9, A-5.6), the annex title as `Agrupamento nome="tituloAnexo"`, and
`Anexos`/`ReferenciaAnexo` on the primary.

### 4.2 `src/lexml_nonstat/render/__init__.py` (modified, additive)

Two new exports: `render_generico_aninhado`, `render_generico_aninhado_from_docx`.
