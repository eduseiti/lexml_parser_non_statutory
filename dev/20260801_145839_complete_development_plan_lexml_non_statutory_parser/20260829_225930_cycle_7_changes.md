## Considered and **rejected**

Five, three of them structural. Recorded because a rejected change is a
decision, and the reasoning is what the next cycle needs.

### R-1 — extending Cycle 3's `segment/` package instead of adding `segments/` — **rejected**

`segment/` has meant *spans* since Cycle 3: it divides a `StyledDoc` into
front matter, body, back matter and annexes, and its docstring's contract is
"nothing is copied and nothing is discarded". Cycle 7's records copy text by
construction. Folding them in would have made half that module's stated
contract false, and would have given one package two unrelated meanings of its
own name. A sibling package costs one plan amendment (**A-7.1**); the
alternative costs every future reader.

*Put to the user, who chose the sibling package.*

### R-2 — normalising `Segment.urn` to an emitter-neutral string — **rejected as major**

The tempting reading of plan §6.1's "segment URNs identical across emitters" is
to *make* them identical: rewrite the id so flat and nested agree. It was
refused. A-5b.4 measured that the two emitters genuinely write different ids,
and a normalised urn resolves against **neither artifact** — feed it to the
document it came from and it selects nothing. The plan asks for a *citable*
address; an address that does not resolve is not one.

`Segment.path` carries the portable half instead, and
`test_every_urn_resolves_in_the_artifact_it_came_from` pins that the literal
half really does resolve — exactly one element, in the document the segment
names. The plan's sentence is amended (**A-7.2**) rather than satisfied
falsely.

*Put to the user, who chose the literal urn plus the path.*

### R-3 — making `Segment.text` cumulative — **rejected**

§6.2's reference stylesheet writes `descendant::p`, i.e. cumulative text, and
matching it in the record would have simplified the CSV writer. But then plan
Cycle 7's own test — "no duplicated text in any segment (Rule B end-to-end)" —
becomes **unwritable**: with cumulative text every ancestor repeats every
descendant, and the corpus's deepest sample would report its leaf paragraphs
four times. Own-text in the record, `full_text` derived for the CSV, keeps both
the invariant and the reference format.

*Put to the user, who chose own-text plus `full_text`.*

### R-4 — teaching `render/common.py`'s `leaf_texts` about segment boundaries — **rejected as major**

The nested reader needs a section's own text *excluding* its subsections'.
The direct route is a `stop=` parameter on `leaf_texts`. Refused: `leaf_texts`
is the single authority on what text an element carries (A-6.4), five modules
and every conservation test depend on its current answer, and a parameter that
changes that answer is a parameter someone will pass by accident. The readers
prune by *element type* before calling it instead — the flat reader skips
`Bloco`, the nested one skips `AgrupamentoHierarquico`, the statutory one skips
the dispositivo children and the echoed `Rotulo` — so `leaf_texts` keeps one
behaviour and the exclusion is visible at each call site.

### R-5 — committing nested-emitter segment goldens as a tenth kind — **rejected**

Symmetrical with the XML goldens, and initially appealing. Refused because the
artifact would assert nothing the three-way oracle does not already assert, and
would *move* whenever the flat emitter changed — a golden diff that means
"something else changed" is worse than no golden, because it trains the
reviewer to regenerate without reading.

## Defects found in this cycle's own code, and fixed

Six. Recorded because a mutation score without its history is a number.

1. **Nested root-level ordering interleaved the front regions with the first
   body section.** `_in_reading_order` sorted `PartePrincipal`'s children by
   `Bloco[@nome='ordem']`, which root-level regions do not carry, so they all
   defaulted to 0 and sorted against the first section's 0. Constraint 1
   applies *inside* an `AgrupamentoHierarquico`; the root's children are
   already in document order. Fixed by not sorting the root level, with the
   reason recorded in a comment.
2. **The model path emitted the back matter before the body**, and took
   A-5b.4's offset from *all* regions rather than the leading ones. Caught by
   `test_three_way_agreement` on 9 of 15 samples — the `order` field
   disagreed. Fixed by walking front → body → back and counting only the
   front.
3. **The `generico-aninhado` preamble id restarted at `agr1`.** Both emitters
   draw the body preamble's ordinal from the *same* allocator the front regions
   used, so `pn_cst_38`'s preamble is `pp1_agr3`, not `pp1_agr1`. Caught by
   comparing model ids against the nested golden.

Two more were found in this cycle's **stylesheets**, both by
`test_xslt_rows_match_python_rows_nested`:

4. **`string-join((descendant::p, descendant::li), ' ')` is sequence
   concatenation, not document order** — all the `p`s, then all the `li`s.
   Fixed with a union (`|`), which yields document order.
5. **The nested stylesheet's cumulative text was in document order, which
   Constraint 1 makes different from reading order.** Fixed with a recursive
   template that emits own prose first, then children sorted by
   `Bloco[@nome='ordem']` — the same rule the Python reader follows.

Both are exactly what a second implementation is *for*: the Python reader was
already right, and only a second derivation could show it.

And one was found by a **test-authoring subagent**, which reported it rather
than fixing it — the standing rule, and the Cycle 6 precedent:

6. **`Segment.route` disagreed with itself inside `ids.py`.** The front/back
   regions and the `tituloAnexo` block copied `model.route` while the body
   hardcoded `"generico"`, so on `port_mf_277` — the corpus's only
   `norma`-routed sample — `segments(model, emitter="generico")` differed from
   `segments(render_generico(model))` on exactly five segments. `route` is the
   one `Segment` field the three-way oracle does **not** compare, which is
   precisely why nothing else would have caught it. Spec decision D-3 settles
   it: route is a property of the **artifact**, and §4.2's fallback makes route
   and emitter genuinely come apart. Fixed with `ids.ROUTE_OF_EMITTER`, one
   table naming what route each emitter's output carries.

   The agent marked it `@pytest.mark.xfail(strict=True)` with the diagnosis in
   the reason string, **parametrised to the one sample that could exhibit it**
   — a blanket marker would have XPASSed on the other fourteen and said
   nothing. When the fix landed the marker turned into an XPASS and the suite
   went red until it was removed. The gap could not become the specification,
   and the fix could not land unnoticed.

## Two dead guards, kept — and the distinction between them

Both surfaced as surviving mutants; both are documented in the code as
defensive rather than load-bearing, because a guard presented as load-bearing
when it is not is the thing worth removing.

- **`_MARKER_BLOCOS` in the nested reader is redundant *in principle*.** Cycle
  6's `leaf_texts` already admits only `rotulo`/`nomeAgrupador` `Bloco`s, so no
  input can reach it. It stays as a statement of intent at the call site: a
  reader should not have to know `leaf_texts`' allowlist to see that `ordem` is
  a marker. The *reachable* form of the defect — widening that allowlist — is
  caught by T-17.
- **`_flat_parent`'s region check is unreachable *from the corpus*, which is a
  different claim.** Measured: a region id is a proper prefix of a body id zero
  times across all fifteen samples, because A-5b.4's shared `agr` sequence
  makes them siblings. But nothing in the id grammar forbids it, and this
  reader is fed files it did not write. `CLAUDE.md` says the corpus stands in
  for 300+ unseen documents; that is exactly the situation where "no sample
  reaches it" is a statement about the sample rather than about the input
  space. Kept, and the reasoning written down where the next reader will find
  it.
