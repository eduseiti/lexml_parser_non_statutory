# Cycle 5 — Changes to Existing Features

- **Cycle:** 5 — Emitter `generico` (flat, default)
- **Date:** 2026-08-28
- **Spec:** [`20260828_184339_cycle_5_spec.md`](20260828_184339_cycle_5_spec.md)

**No delivered behaviour changed.** This is an additive cycle: it adds a package
(`render/`), a model type (`DocumentModel`), a sixth golden kind, and promotes two private
helpers to public so they are reused rather than reimplemented. Every one of the 3135 tests
inherited from Cycles 0–4b passes unmodified, and all 90 pre-existing golden files are
byte-identical after regeneration.

## Minor changes (made, logged, continued)

### C-1 · `segment/render.py` — `_agrupamento` → `agrupamento_block`

| Field | Content |
|---|---|
| What changed | `src/lexml_nonstat/segment/render.py`, private `_agrupamento` renamed to public `agrupamento_block`; added to `__all__` and re-exported from `segment/__init__.py` |
| Before → after | The function is **unchanged** — same arguments, same element, same output. Only its name and visibility changed |
| Why | Cycle 5 renders the front/back matter **regions** (change C-5 below) and must produce the same `<Agrupamento nome=…><p>…</p></Agrupamento>` shape Cycle 3 produces. Amendment A-3.4's rule is that a second implementation of a settled decision is a second source of truth |
| Blast radius | None. `render_front_generico` and `render_back_generico` call it internally and are byte-identical; `tests/unit/test_segment_render.py`'s 25 tests pass unchanged |
| Plan impact | None |

### C-4 · `scripts/regen_goldens.py` — `KINDS` gains an extension, renderers return a mapping

| Field | Content |
|---|---|
| What changed | `KINDS[kind]` was `(directory, renderer)` with `renderer(sample) -> str`; it is now `(directory, renderer, extension)` with `renderer(sample) -> dict[str, str]` mapping a *file-stem suffix* to content. `golden_path(sample, kind)` gains a third parameter `suffix=""`. `regenerate()` writes every file the renderer returns and reports the strongest state across them |

| Blast radius | Script-internal. `golden_path` and `KINDS` have no callers outside the script — the five golden test modules locate their own directories. Verified by grep and by regenerating everything |

### C-5 · Front and back matter are rendered as **regions**, not as parts

| Field | Content |
|---|---|
| What changed | New `render/common.py` gains `front_region()` / `back_region()`. Cycle 3's `render_front_generico` / `render_back_generico` are **left exactly as delivered** — no signature change, no output change, still tested — and are simply not what the whole-document emitter calls |
| Before → after | Cycle 3's functions render the *named parts* (epigraph, ementa, preamble, formula, signatures, closing date). The region functions render the whole **hull** in document order, emitting each named part identically and each maximal run of unclaimed non-empty blocks as `Agrupamento nome="preliminar"` (front) / `nome="nota"` (back) |
| Why | **Measured**: 40 non-empty blocks across 6 samples sit inside a hull and inside no named part, so a parts-based emitter loses them and fails invariant #2 on day one. `parecer_93` loses 21 (portal stamp, institutional banner, `NUP:`/`INTERESSADOS:`, and 14 blocks of closing matter), `pn_cst_38` 7 (`De acordo`, `Publique-se` and a classification header sitting *between* its two signature blocks), `REsp_1306393` 7, `par_cosit_26` 3, `adn_cst_10` 1, `port_mf_454` 1. This is not a Cycle 3 defect: `FrontMatter.span` is deliberately the contiguous hull (amendment A-3.5) so that the parts partition the document — the gap was between segmentation and rendering, and rendering is this cycle |
| Blast radius | None on delivered behaviour. Two new regression tests (`test_front_region_covers_the_hull`, `test_back_region_covers_the_hull`) and the conservation suite pin it |
| Plan impact | New amendment **A-5.1** |

## Changes considered and **rejected**

| Considered | Rejected because |
|---|---|
| Extending Cycle 3's `render_front_generico` / `render_back_generico` with a `residue=True` flag so they render hulls | It puts two behaviours behind one name and risks the delivered output of a function 25 tests pin. The regions are a *different* thing — the hull, not the parts — and deserve a different name. Cycle 3's functions stay byte-identical |
| Giving the front matter a distinct id token (`pp1_fm1`) to avoid colliding with section ids | It changes ids Cycle 3 already emits (a **major** change), *and* `pp1_fm_agr1` would break Rule A, whose proper prefix `pp1_fm` would not exist as an `Agrupamento`. Continuing Cycle 3's `pp1_agr{n}` sequence (spec decision D-1) needs no change to Cycle 3 at all |
| Rendering the annex inline, as another `Agrupamento` in the primary `PartePrincipal` | Simpler and trivially conserving, but it drops a listed Cycle 5 deliverable (`Anexos`/`ReferenciaAnexo`) and diverges from the reference parser's convention (§2.9), which is what makes our output interoperable with existing statutory tooling. Put to the user as Q3; the sibling bundle was chosen |
| Preserving inline formatting (`b`/`i`/`sup`) inside the front and back matter regions | Cycle 3 renders those regions as plain text lines, and matching it keeps one shape. The *text* is conserved either way, and conservation is what the invariant is about. Recorded here so a later cycle can revisit it deliberately rather than by accident |
| A sixth serialisation (`DocumentModel.to_json`) and a `model` golden kind | Its five components already have byte-stable goldens; a sixth would make one behaviour change diff twice (spec decision D-3) |
