### 2.2 Non-blocking decisions taken myself

1. **`MetadadoProprietario` shape.** The schema requires a `fonte` URI attribute (`attributeGroup name="source"`) and extends `xsd:anyType`, so children are unconstrained. Verified by probe that one `<MetadadoProprietario fonte="…">` holding `<campo nome="NUP">value</campo>` children **validates on both schemas**. One element holding all fields, rather than one element per field — fewer nodes, same information.
2. **`fonte` value** is `http://www.lexml.gov.br/nonstat` (a stable identifier for this parser as the metadata's origin), not a per-document URI.
3. **Module layout** follows the plan's §3 tree exactly: `model/urn.py`, `model/metadata.py`, `profile/{base,registry,parecer,ato_declaratorio,portaria,servico,jurisprudencia_generico,generic}.py`.
4. **Test file organisation:** `tests/unit/test_urn.py`, `tests/unit/test_metadata.py`, `tests/unit/test_profiles.py`, and metadata goldens under `tests/golden/metadata/` beside Cycle 1's `styled/`, regenerated by the same `scripts/regen_goldens.py`.
5. **Roman-numeral and ordinal handling** in number parsing is out of scope — no sample numbers a document in roman.

### 2.3 Plan claims corrected by measurement

Both are recorded here and will become plan amendments (§6 of the report):

- **`parecer_93`'s date is not what the plan implies.** Plan §8 lists "`parecer_93` → … date `2018-12-28`" among Cycle 2's tests without saying where it comes from. It is not on the epigraph line (`PARECER n. 00093/2018/DECOR/CGU/AGU` carries no date). It is a bare `28/12/2018` stamp at block 0 — a *header artifact*, not a legal date; the document was signed on 19/12/2018. The expectation is kept per decision #1, but the extraction rule that satisfies it is a documented fallback chain, not "read the epigraph".
- **The plan's `MetadadoProprietario` field list is under-specified for the corpus.** It names `NUP`, `INTERESSADOS`, `ASSUNTO`, `Cod. Ement.` (all from `parecer_93`). A census across all 15 samples finds a further set that belongs in the same channel: `Assunto`, `Ementa`, `Dispositivos Legais` (`par_cosit_26`), `JURISPRUDÊNCIA` (`ad_pgfn_*`), `Referência`, `Precedentes` (`sumula_stj_125`), `INTERESSADA` (`parecer_93`'s despacho). The allowlist covers these.

## 3. Expanded goals

### 3.1 `model/urn.py`

```python
LEXML_URN_RE: re.Pattern          # validates the urn:lex: grammar we emit

@dataclass(frozen=True)
class UrnDate:
    year: int
    month: int | None = None
    day: int | None = None
    @property
    def urn_repr(self) -> str     # "2018-06-07" or "2018"

def slugify_authority(text: str) -> str
    """NFKD accent-fold → lowercase → dotted slug.
    'MINISTÉRIO DA FAZENDA' -> 'ministerio.fazenda'"""

def build_urn(*, locality: str = "br", authority: str, doc_type: str,
              date: UrnDate | None, number: str | None,
              fragment: str | None = None) -> str
    """urn:lex:<locality>:<authority>:<doc_type>:<date>;<number>[!<fragment>]"""

def parse_urn(urn: str) -> UrnParts
def is_valid_urn(urn: str) -> bool
```

`build_urn` mirrors `Metadado.scala:145` (`urn:lex:$localidade:$autoridade:$tipoNorma:${id.urnRepr}`) and `Id.urnRepr` (`anoOuDataUrn + ";" + num`). The `!fragment` suffix is the annex convention from plan §2.9 (`!anexo1`), needed by Cycle 6.

### 3.2 `model/metadata.py`

```python
@dataclass(frozen=True)
class ProprietaryField:
    label: str
    value: str
    source_index: int             # StyledPara.index it came from

@dataclass(frozen=True)
class Metadata:
    profile: str
    locality: str = "br"
    authority: str | None = None
    doc_type: str | None = None
    number: str | None = None
    date: UrnDate | None = None
    date_source: str | None = None      # epigraph|header|signature|filename
    authority_source: str | None = None # epigraph|preamble|profile
    epigraph: str | None = None         # the raw epigraph line, if found
    epigraph_index: int | None = None
    proprietary: tuple[ProprietaryField, ...] = ()

    @property
    def urn(self) -> str                # best-effort, always syntactically valid
    @property
    def complete(self) -> bool          # authority, doc_type, number, date all present
    @property
    def missing(self) -> tuple[str, ...]
    def to_dict(self) / from_dict(...)  # golden round-trip, Cycle 1 convention
    def to_xml(self) -> etree._Element  # <Metadado> only (decision #6)

def extract_metadata(doc: StyledDoc, *, profile=None, filename=None) -> Metadata
```

`to_xml()` emits:

```xml
<Metadado>
  <Identificacao URN="urn:lex:br:ministerio.fazenda:portaria:2018-06-07;277"/>
  <MetadadoProprietario fonte="http://www.lexml.gov.br/nonstat">
    <campo nome="NUP">03154.004642/2018-50</campo>
  </MetadadoProprietario>
</Metadado>
```

`MetadadoProprietario` is omitted entirely when there are no fields (`minOccurs="0"`).

### 3.3 `profile/base.py` + `profile/registry.py`

```python
@dataclass(frozen=True)
class DocumentProfile:
    name: str
    urn_type: str                       # "parecer", "portaria", "ato.declaratorio"
    urn_authority: str | None           # default when the document doesn't say
    urn_locality: str = "br"
    epigraph_res: tuple[re.Pattern, ...] = ()
    authority_res: tuple[re.Pattern, ...] = ()   # preamble openers
    field_labels: frozenset[str] = frozenset()   # the allowlist (decision #4)
    ementa_absent: bool = False
    score(doc: StyledDoc) -> float      # 0.0–1.0 confidence this profile applies

def register(profile) / get_profile(name) / all_profiles() / select_profile(doc) -> DocumentProfile
```

`select_profile` scores every registered profile over the document's first ~30 non-empty paragraphs and returns the highest; `generic` scores a constant floor so it always wins when nothing else matches. Ties break by registration order, deterministically.

### 3.4 Extraction rules

**Epigraph + number + date.** Primary pattern, matching 11 of 15 samples on block 0:

```
<Tipo> <Sigla?> nº <N>, de <D> de <mês> de <AAAA>
```

Fallbacks in order: `PARECER n. 00093/2018/DECOR/CGU/AGU` form (number `00093` → `93`, per the plan's normalisation test); `SÚMULA N. 125`; `Súmula CARF nº 42`; `RECURSO ESPECIAL Nº 1.306.393 - DF`.

**Date chain** (decision #1, #3): epigraph date → bare header stamp (`^\d{2}/\d{2}/\d{4}$` in the first blocks) → signature date (`Brasília, 19 de dezembro de 2018`) → filename (`_YYYYMMDD`) → `None`. `date_source` records which fired.

**Authority chain:** epigraph sigla (`MF` → `ministerio.fazenda`, `PGFN` → `procuradoria.geral.fazenda.nacional`, `SRF` → `ministerio.fazenda;secretaria.receita.federal`, `CARF`, `STJ`, `AGU`, `Cosit`/`CST`) → preamble opener (`O MINISTRO DE ESTADO DA FAZENDA` → `ministerio.fazenda`) → the profile's default → `federal`.

**Number normalisation:** strip leading zeros and thousands separators — `00093/2018` → `93`, `1.306.393` → `1306393`.

**Proprietary fields:** for each paragraph in the front-matter region (up to the first body paragraph, capped at 40 blocks), capture `LABEL: value` only when `LABEL` is in the profile's allowlist (case- and accent-insensitive), or is ALL-CAPS and ≤4 words. `Cod. Ement.34` (no colon, `parecer_93` block 16) is matched by an explicit pattern, since the plan names it.

## 7. Risks

| Risk | Mitigation |
|---|---|
| Authority slugs are invented rather than sanctioned; the real LexML authority vocabulary is an external registry we don't have | Slugs follow the reference parser's observed convention (`senado.federal`, `ministerio.fazenda`). Recorded as a known limitation; Cycle 8/9 can map to an official list without touching callers, since `build_urn` takes the slug as a parameter. |
| The date fallback chain is tuned to 15 samples and may mis-fire on the 300+ corpus | `date_source` is recorded on every extraction, so a corpus run can be audited by source; the header-stamp branch is the weakest and is ordered *after* the epigraph. |
| The field allowlist under-captures on unseen documents | Deliberate, per decision #4: a missed field is recoverable (the text stays in the body), a false field is silent corruption. The ALL-CAPS heuristic gives bounded recall for unseen labels. |
| `pn_cst_38` shares the `parecer` profile despite a different front matter | Accepted per decision #5; its subject-code lines land in the body, not in metadata, which is correct for Cycle 3/4 to segment. |
