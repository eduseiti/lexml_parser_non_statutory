## 2. Reconciliation outcomes

### Asked, and answered by the user

**R-1 — package name.** Plan §6.1 says `segmentation/api.py`, but
`src/lexml_nonstat/segment/` already exists (Cycle 3, front/back-matter
*spans*). **Decision: a new `segments/` package** (plural), holding the citable
`Segment` records. `segment/` keeps its Cycle 3 meaning untouched. The plan's
`segmentation/` name is amended (**A-7.1**) with the collision recorded as the
reason.

**R-2 — what "segment URNs identical across emitters" means.** A-5b.4 measured
that it is false as string equality. **Decision: `Segment.urn` carries the
literal, resolvable `{document urn}!{id}` of the artifact it came from, and a
second field `Segment.path` carries the emitter-independent address** — the
tuple of body-section ordinals. The three-way oracle compares `path` (plus
text, kind, label, heading, breadcrumb); `urn` is compared only within one
emitter, where it *is* stable. This makes both halves of the plan's intent
assertable at full strength instead of choosing between a false test and a
URN that resolves to nothing (**A-7.2**).

**R-3 — `hierarchy_from_xml()` scope.** **Decision: it returns a `HierarchyDoc`
and reads all three emitters' output** — flat, nested and `norma`. Fields the
XML cannot carry (`Evidence`, `confidence`, `DocSignals`) come back at their
defaults, and a test asserts that explicitly rather than leaving it implied.
The reader dispatches on the document element (`DocumentoGenerico` vs `Norma`)
and, within `DocumentoGenerico`, on whether `AgrupamentoHierarquico` is present
— never on `RenderedDocument.emitter`, which a file read from disk does not
have.

**R-4 — XSLT scope.** **Decision: all three stylesheets ship, and their rows are
asserted equal to the Python API's rows** (skipped, with a reason, when
`saxonche` is absent). The community `GeraCSVporArtigoPorAgrupador.xsl` probe
runs and its result is recorded as informational, not gating.

**R-5 — segment text.** **Decision: `Segment.text` is leaf-only** — the
section's own prose, excluding descendants — so concatenating every segment
reproduces the document's words exactly once and the plan's "no duplicated text
in any segment" test is writable. `Segment.full_text` gives the cumulative form
(section + descendants) that §6.2's `descendant::p` idiom produces, for
consumers that want it. Both derive from Cycle 6's `leaf_texts`; this module
does **not** become a second text authority (the A-3.4 rule).

**R-6 — goldens.** **Decision: one new golden kind, `segments`, JSONL**, written
from the model (the primary path), one file per sample plus one per annex
document, matching the existing `.anexo1` suffix convention. CSV is covered by
unit tests rather than committed as a second copy of the same rows.

### Decided here, not asked (non-blocking)

- **D-1 — module layout.** `segments/model.py` (the `Segment` record),
  `segments/api.py` (`segments()` and the three readers), `segments/roundtrip.py`
  (`hierarchy_from_xml`), `segments/writers.py` (CSV/JSONL),
  `segments/xslt.py` (the Saxon driver), `segments/stylesheets/*.xsl`,
  `segments/__init__.py` (the public surface), `segments/__main__.py` (a
  `python3 -m lexml_nonstat.segments` dump, matching the pattern every other
  package already follows).
- **D-2 — stylesheets are package data**, under
  `src/lexml_nonstat/segments/stylesheets/`, added to
  `[tool.setuptools.package-data]` beside `validate/stubs/*.xsd`. They are
  runtime artifacts the API can invoke, not scripts.
- **D-3 — `Segment.route` (plan §6.1's field) is populated from the artifact,
  not re-inferred**: `model.route` on the primary path, and on the XML paths the
  document element (`Norma` → `norma`, else `generico`). A reader that
  re-derived the route would be a second router.
- **D-4 — breadcrumb is `list[str]` of ancestor titles**, root-first, excluding
  the segment itself, per §6.1's field name. A section with neither label nor
  heading contributes its `title` — which is `""` — so the breadcrumb records
  the *depth* honestly rather than silently collapsing. Tested.
- **D-5 — `Segment` is frozen and has `to_dict`/`from_dict`**, in the Cycle 1–4
  house style, because the JSONL writer and the goldens both need it.
- **D-6 — front/back-matter regions are segments too.** They are `Agrupamento`
  children of `PartePrincipal` with real ids and real text; excluding them would
  make "no text is missing from the segments" unassertable. They carry
  `path=()` — they are not body sections — and `kind` is their `@nome`
  (`epigrafe`, `ementa`, `assinatura`, …).
- **D-7 — annexes segment as separate documents**, each with its own document
  URN (`…!anexo1`), which is what `port_mf_277`'s "segments span primary **and**
  annex" test requires. `segments()` over a bundle yields primary segments then
  each annex's, in document order.

## 3. Expanded goals

### 3.1 `segments/model.py`

```python
@dataclass(frozen=True)
class Segment:
    urn: str                        # "{document urn}!{id}" — resolvable in ITS artifact
    id: str                         # the raw element id
    kind: str                       # secao | subsecao | artigo | caput | epigrafe | …
    level: int                      # 1-based depth; 0 for a front/back region
    label: str | None               # rótulo as written
    heading: str | None             # nomeAgrupador
    breadcrumb: tuple[str, ...]     # ancestor titles, root-first, excluding self
    text: str                       # OWN text only (Rule B)
    route: str                      # generico | norma
    path: tuple[int, ...]           # emitter-independent body address; () for a region
    order: int                      # 0-based document-order position among siblings
    document: str = ""              # document URN this segment belongs to

    @property
    def full_text(self) -> str: ...      # own text + descendants', document order
    @property
    def depth(self) -> int: ...          # len(breadcrumb)
    def to_dict(self) -> dict: ...
    @classmethod
    def from_dict(cls, data) -> "Segment": ...
```

`full_text` needs the descendants, so segments are produced as a **tuple**
(document order) and each knows its children's indices internally; the public
API yields `Segment` objects whose `full_text` is precomputed at build time.

### 3.2 `segments/api.py`

```python
def segments(source, *, emitter: str | None = None) -> tuple[Segment, ...]
```

The one entry point §6.1 names. Dispatches:

| `source` | Path |
|---|---|
| `DocumentModel` | the **primary** path — straight off the `HierarchyDoc`, no XML |
| `RenderedDocument` | its bundle's documents, via the XML readers |
| `etree._Element` / `str` / `Path` | one XML document, via the XML readers |

`emitter=` is accepted only for the `DocumentModel` case, choosing which
emitter's ids the segments should carry (`"generico"` default,
`"generico-aninhado"`, `"norma"`). This is what makes `urn` literal *and*
lets the three-way oracle compare like with like.

```python
def segments_from_model(model, *, emitter="generico") -> tuple[Segment, ...]
def segments_from_flat_xml(doc)   -> tuple[Segment, ...]   # id-path reconstruction, Rules A/B
def segments_from_nested_xml(doc) -> tuple[Segment, ...]   # native ancestry; parses NO ids for structure
def segments_from_norma_xml(doc)  -> tuple[Segment, ...]   # statutory elements
```

Contracts, each of which is a test:

- **`segments_from_flat_xml`** reconstructs ancestry from the id path (§2.4's
  Rules A/B). It reads `Bloco nome="rotulo"/"nomeAgrupador"/"nivel"`.
- **`segments_from_nested_xml` parses no `id`s at all** *for structure* — it uses
  `AgrupamentoHierarquico` ancestry and `Bloco nome="ordem"`. It reads the `id`
  attribute **only** to fill `Segment.id`/`Segment.urn`, which is a value it
  copies, not structure it infers. The plan's test — mutate every `id`, segments
  unchanged — is therefore asserted on **everything but `id`/`urn`**, and the
  test says so.
- **Order comes from `Bloco nome="ordem"` or, absent it, the source index —
  never sibling position** (§5.4 Constraint 1). A nested document whose children
  are serialised in a different order than they were read still segments in
  reading order.
- **`segments_from_norma_xml`** walks `Artigo`/`Caput`/`Paragrafo`/`Inciso` plus
  `ParteInicial`/`ParteFinal` regions, and uses Cycle 6's `ARTIGO_ID_RE` grammar
  for depth rather than the `_`-path arithmetic (the two id grammars, A-6.1).

### 3.3 `segments/roundtrip.py`

```python
def hierarchy_from_xml(doc) -> HierarchyDoc
```

Rebuilds Cycle 4's `HierarchyDoc` from any emitted document or bundle.
Reconstructs `Section(label, heading, level, kind, body, children)` with `Para`
bodies; `Evidence`, `confidence`, `flat`, `DocSignals` come back at defaults —
asserted explicitly, so a future reader that pretends to recover them fails.
Round-trip claim: **tree shape and all text are preserved**, i.e.
`walk()`-order `(kind, label, heading, level)` tuples and the word multiset are
equal to the original model's.

### 3.4 `segments/writers.py`

```python
def to_csv(segments, stream=None, *, header=True) -> str
def to_jsonl(segments, stream=None) -> str
CSV_COLUMNS: tuple[str, ...]   # ("tipo","nivel","rotulo","breadcrumb","texto","urn")
```

CSV columns follow §6.2's stylesheet header verbatim, so the XSLT and Python
paths are comparable row for row. `csv.writer` with `QUOTE_MINIMAL` and `\n`;
breadcrumb joined with `" | "`, matching the stylesheet.

### 3.5 `segments/xslt.py`

```python
HAVE_SAXON: bool
STYLESHEETS: dict[str, Path]   # "generico" | "generico-aninhado" | "norma" | "community"
def transform(document, stylesheet) -> str          # raises SaxonUnavailable if absent
def rows(document, stylesheet) -> tuple[tuple[str, ...], ...]
class SaxonUnavailable(RuntimeError): ...
```

Three stylesheets are written: `segment_generico.xsl` (§6.2's, with Rules A/B),
`segment_generico_aninhado.xsl` (native ancestry), `segment_norma.xsl`
(statutory elements, adapting the community stylesheet). All emit
`CSV_COLUMNS`.

### 3.6 `scripts/regen_goldens.py`

A ninth kind, `segments`, `.jsonl`, one file per emitted document
(`""`, `".anexo1"`), written from the model on the **flat** emitter's ids —
the default emitter, matching what `--kind=generico` commits.

## 7. Risks

1. **The nested reader is the one that must not cheat.** The easy
   implementation reads the id path — which would make T-10 fail, and if T-10
   were written weakly it would pass a reader that had silently become a second
   copy of the flat one. Mitigation: T-10 mutates *every* id and the reader is
   written with no `_`-splitting in the nested path at all.
2. **`full_text` invites duplication.** If `text` were cumulative, T-6 becomes
   unwritable — this is exactly R-5's reason. Mitigation: one function computes
   own-text from `leaf_texts`, and `full_text` is composed from the tuple.
3. **The community-stylesheet probe may embarrass the plan.** §6.2 predicts it
   "runs unmodified on nested output". Pre-measured: it emits **header only**
   for both `generico` and `generico-aninhado`, and 4 data rows for `norma`,
   because it selects on statutory element *names* and never mentions
   `AgrupamentoHierarquico`. The test records the measurement; the report states
   what it means for §11's reply to the maintainers.
4. **The norma reader spans two id grammars.** A-6.1's ids do not decompose by
   `_`-path arithmetic the way `pp1_agr1_agr2` does (`art1_cpt` is not a child
   of `art1_cpt`'s "parent path" in the same sense). Mitigation: separate
   reader, dispatching on element name, never on id shape.
5. **Nine golden kinds ×15 samples is a lot of artifacts to keep honest.**
   Mitigation: the goldens assert properties (breadcrumb completeness,
   conservation, uniqueness) read from disk, not just byte equality — a
   regenerated-but-wrong golden still fails.
