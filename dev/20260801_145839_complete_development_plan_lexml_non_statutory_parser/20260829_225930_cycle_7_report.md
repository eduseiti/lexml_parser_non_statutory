## 1. Summary

**Verdict: complete.**

Segmentation output is delivered. The `segments/` package turns any of the
three emitters' artifacts — or the in-process model, which is the primary path
— into citable `Segment` records, and **the three-way oracle A-R.5 asks for
agrees on all fifteen samples**: the model walker, the flat-XML reader and the
nested-XML reader reach the same segments by genuinely different routes, one
composing ids arithmetically, one reconstructing ancestry from the id path, one
reading containment and parsing no ids at all.

Three stylesheets ship, and their rows are required to equal the Python API's
on all **34 emitted documents**. That comparison is not decoration: it found
two real defects in the stylesheets, both of them consequences of facts this
project had already recorded but the XSLT idiom quietly violates.

Six amendments, four of them contradicting the plan:

- **A-7.1** — the package is `segments/`, not §6.1's `segmentation/`:
  `lexml_nonstat.segment` has meant *spans* since Cycle 3.
- **A-7.2** — **"segment URNs identical across emitters" is false as string
  equality**, and A-5b.4 had already measured why. `Segment` carries two
  addresses: a literal `urn` that resolves in its own artifact, and a portable
  `path` that is identical across all three derivations.
- **A-7.3** — there are **three** readers, not two, and dispatch is on markup
  rather than on `RenderedDocument.emitter`, which a file read from disk does
  not have.
- **A-7.4** — **the nested oracle leg does not skip.** §8 says it skips without
  the capability; measured, reading nested XML needs no schema at all.
- **A-7.5** — order is `Bloco nome="ordem"`, not §6.1's `Rotulo`: a rótulo is
  not sortable, which is the same finding A-5b.2 already recorded.
- **A-7.6** — **the community stylesheet produces no rows for either
  `generico` shape**, and that sharpens §11's argument rather than weakening
  it.

**Subagent A's defect, and why the reporting mechanism earned its place.**
`Segment.route` was inconsistent inside my own `ids.py`: the front/back regions
and the `tituloAnexo` block copied `model.route` while the body hardcoded
`"generico"`. On `port_mf_277` — the corpus's only `norma`-routed sample —
`segments(model, emitter="generico")` therefore disagreed with
`segments(render_generico(model))` on exactly five segments. Spec decision D-3
says route is a property of the **artifact**: a `DocumentoGenerico` is
`generico` however §4.4 classified the DOCX, and §4.2's fallback makes the two
genuinely come apart. Fixed with `ids.ROUTE_OF_EMITTER`, one table that says
what route an emitter's output carries.

The agent marked it `@pytest.mark.xfail(strict=True)` with the full diagnosis
in the reason string, and **parametrised the marker to the one sample that
could exhibit it** — a blanket xfail would have XPASSed on the other fourteen
and said nothing. When the fix landed, the strict xfail turned into an XPASS
and the suite went red until the marker was removed. The gap could not become
the specification, and the fix could not land unnoticed.

**Both subagents corrected the spec where the corpus contradicted it, and
strengthened rather than weakened the assertion each time.** Four cases, all
worth recording because each is a place the spec's own expected-value column
was wrong about the fifteen documents:

- **T-13 assumed every sample has front/back regions.** `CARNE_LEAO` has
  **zero** — it is an untitled excerpt, all body. Asserted by name rather than
  guarded with `if regions:`, which would have let the other fourteen silently
  lose theirs.
- **T-17 as written is false of correct output.** "No segment's text contains
  an order integer" fails because `sumula_stj_125`'s section 6 legitimately
  contains "6". Replaced with a **differential** test: poison every marker
  `Bloco` with a sentinel, re-segment, assert no text moved — and tie marker
  presence to body-section count so the loop cannot go vacuous.
- **T-9 met an element that cannot be addressed at all.** `Assinatura` has no
  `id` in the LexML base schema, so its segment's urn has an empty fragment.
  Rather than skipping id-less segments as a class, the test asserts it is the
  **only** one in the corpus.
- **T-24's phrasing is unachievable and the honest replacement is stronger.**
  "`model → xml → model' → xml'` byte-identical" fails on all 15 × 2, because a
  section's own text comes back as one joined `Para`. Subagent B measured and
  asserted the real property instead: the round trip reaches a **fixpoint after
  one pass** — `model'₁ == model'₂` and `xml₂ == xml₃` byte-for-byte — which
  bounds the erosion at exactly one pass. Byte-equality of pass 1 vs 2 would
  never have proven that. A companion test asserts the loss is *real*, so the
  weaker form is not an excuse, and will fail if `_paras` ever recovers
  paragraph boundaries.

**Subagent A also found that the spec's own T-10 recipe was insufficient for
the risk it names.** Prefixing every id with `"X"` leaves `Xpp1_agh1_agh2` —
still four ascending `_`-separated steps — so a reader deriving depth from
`id.count("_")` passes it. T-10 now replaces every id with a flat opaque token
carrying no separators, assigned in *serialised* order, which Constraint 1
guarantees is not reading order. The mutation it was written for is now caught.

**Verified, not trusted.** `git diff --stat src/ scripts/` shows only my own
files. I re-ran the full suite, the golden regeneration, the schema check, the
bare-checkout run and both mutation sweeps myself, and independently
re-measured subagent A's two dead-guard claims rather than accepting them.

  `full_text` and `csv_row` temporarily returning own-text.

**The five survivors are all unreachable code, diagnosed rather than papered
over.** A mutation score quoted without its survivors is a number, not evidence
(the Cycle 6 precedent), and the five split into two kinds:

*Redundant in principle — a rule enforced upstream:*

1. `_MARKER_BLOCOS` in the nested reader. Cycle 6's `leaf_texts` already admits
   only `rotulo`/`nomeAgrupador` `Bloco`s, so a marker cannot reach a segment's
   text with or without the guard. **The reachable form of this defect —
   widening `leaf_texts`' own allowlist — is caught**, by T-17.
2. `_annex_tree_of`'s `pop` of the `tituloAnexo` segment: that segment has
   `path == ()`, so `_tree_from_segments` skips it as a region regardless.
3. `_annex_fragment`'s URN-fragment branch: the `PartePrincipal/@id` fallback
   strips `_pp` and returns the same `anexo1`. Genuinely equivalent **on this
   corpus** — it would differ only on a document with no `!fragment` *and* a
   root not suffixed `_pp`.

*Unreachable from the corpus, but not from the input space — and therefore
kept deliberately:*

4. `_flat_parent`'s `candidate not in region_ids` check. Measured across all
   fifteen samples: a region id is a proper prefix of a body id **zero** times,
   because A-5b.4's shared `agr` sequence makes them siblings. But nothing in
   the id grammar forbids it, and this reader is fed files it did not write.
   The corpus stands in for 300+ unseen documents, which is exactly the
   situation where "no sample reaches it" is a statement about the sample.
5. The same reasoning applies to the flat reader's gapped-path fallback, which
   this pipeline cannot produce and a hand-edited file can.

Each is now documented **in the code** as defensive rather than load-bearing,
so the distinction survives the next reader.

## 7. Deviations and open items

- **§6.1's `Segment` field list is delivered wider than written.** The plan
  names eight fields; the record has fourteen. Each addition is forced and
  recorded: `path` and `id` by A-7.2, `order` by A-7.5, `document` because an
  annex is a separate document (§2.9), `echoed_label` by A-6.4, and
  `descendant_texts` so `full_text` is derivable from the record alone rather
  than only from the tree it came from.
- **Paragraph boundaries do not survive the round trip.** A section's own text
  comes back as **one** `Para`, because the readers report own-text as a single
  joined string. So the round-trip claim is *tree shape and word conservation*,
  not node identity — stated in `roundtrip.py`'s own docstring, and the reason
  the spec's "byte-identical re-render" row was replaced by an honest
  idempotence test rather than quietly dropped. Formatting (`Inline` runs, bold,
  hyperlinks) does not survive either: the XML records what the text says, not
  which runs were bold.
- **`Evidence` and `confidence` deliberately do not round-trip.** No emitter
  writes them, because the XML is the document rather than the reasoning that
  produced it. They come back at their defaults and
  `test_roundtrip_does_not_fabricate_evidence` asserts those defaults *by
  value*, so a future reader cannot quietly start guessing them.
- **A gapped flat id path degrades rather than fails.** Rule A makes the
  reconstruction possible; when a hand-edited file breaks it, the orphan is
  attached to the nearest ancestor that does exist rather than dropped. No text
  is lost and the gap is visible in the breadcrumb. Unreachable from this
  pipeline, which cannot emit a gap by construction, so it is tested against a
  hand-built document.
- **The segment goldens are committed for the flat emitter only.** The nested
  emitter's segments would restate what the three-way oracle already asserts,
  and would move whenever the *flat* emitter changed. Recorded as R-5 in the
  changes log.
- **The `norma` reader covers `Artigo`/`Caput`/`Paragrafo`/`Inciso` only.**
  `Alinea` and `Item` are not read because Cycle 6 does not emit them — no
  corpus document reaches them (its own open item, A-2.4's reasoning). A
  document needing them falls back to `generico`, which segments fine.
