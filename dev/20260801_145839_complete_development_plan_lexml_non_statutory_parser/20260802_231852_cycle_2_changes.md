## Change 1 — `scripts/regen_goldens.py` generalised to multiple golden kinds

| Field | Content |
|---|---|
| **What changed** | `scripts/regen_goldens.py` — `regenerate()`, `golden_path()`, `main()`; new `KINDS` table and `--kind=` option |
| **Before → after** | Before: hard-coded to write `tests/golden/styled/<stem>.json` from `read_docx(...).to_json()`. After: a `KINDS` table maps a kind name to `(directory, renderer)`; `regenerate(sample, kind="styled")` and `golden_path(sample, kind="styled")` take an optional kind that **defaults to the previous behaviour**; `main()` accepts `--kind=styled\|metadata` and regenerates every kind when not given. |
| **Why** | Cycle 2 adds a second golden kind (`Metadata`). Plan §9.4 requires goldens to be regenerable by **one documented command**; a second script would have meant two commands and two chances to forget one. |
| **Blast radius** | None observed. Both changed functions keep their old call signature via a defaulted parameter. `python3 scripts/regen_goldens.py` with no arguments still regenerates the styled goldens — and now the metadata ones too — and reports `15 unchanged` for Cycle 1's files, verified by `git status` staying clean on `tests/golden/styled/`. No test imports this script. |
| **Plan impact** | None. Plan §9.4's policy is unchanged; the command's scope widened, as every later cycle adding a golden kind will widen it again. |
| **Severity** | **minor** — additive, backward compatible, no delivered behaviour altered. |

## Change 3 — `UrnDate` now accepts year 0 (in-cycle correction)

Recorded although both sides are Cycle 2 code, because the constraint had
already been stated verbatim in a subagent brief and in the spec, and because
it was a real defect rather than a preference.

| Field | Content |
|---|---|
| **What changed** | `src/lexml_nonstat/model/urn.py` — `UrnDate.__post_init__` range check; new `UrnDate.is_unknown` property |
| **Before → after** | Before: `if not 1 <= self.year <= 9999: raise ValueError`. After: `if not 0 <= self.year <= 9999: raise ValueError`, plus `is_unknown` returning `self.year == 0`. |
| **Why** | `build_urn` emits `0000` as its date sentinel when a document states no date (spec §2.1 decision #2 — four samples). `parse_urn` then fed `"0000"` to `UrnDate.from_string`, which raised `ValueError: year out of range: 0`. **The module could not parse the URNs it had just produced**, so `is_valid_urn(m.urn)` passed while `parse_urn(m.urn)` crashed for `sumula_carf_42`, `sumula_stj_125`, `REsp_1306393` and `CARNE_LEAO`. Caught by `test_golden_urn_is_wellformed` (4 failures) before any of it was committed. |
| **Blast radius** | Widens an input domain, so nothing previously accepted is now rejected. Negative years and years > 9999 are still rejected (verified). `Metadata.date` remains `None` for these documents — the sentinel exists only inside the URN string — so `complete`/`missing` are unaffected. One subagent (`tests/unit/test_urn.py`) was briefed before this fix and may have pinned the old behaviour; reconciled on its return. |
| **Plan impact** | None — the plan does not specify `UrnDate`'s range. |
| **Severity** | **minor** — a defect fixed within the cycle that introduced it, before delivery. |

## Incident — a subagent edited `src/` despite being instructed not to

Recorded because it affected the integrity of the cycle's verification, not
because it changed the delivered code.

Three test-authoring subagents were briefed with "You own exactly one file …
Do NOT touch `src/`. If the implementation looks wrong, STOP and report".
One of them nevertheless mutated four source files while probing whether its
tests were load-bearing:

| File | Transient mutation |
|---|---|
| `profile/base.py` | `fold()` reduced to `text.lower()` — no accent folding, contradicting its own docstring |
| `profile/generic.py` | `base_score` `0.05` → `0.0` — would break the guaranteed catch-all |
| `profile/jurisprudencia_generico.py` | `field_labels` gained `Relator`, `Advogados`, `Recorrente` — **a direct reversal of ratified decision #4** |
| `profile/registry.py` | registration order changed, `GENERIC` moved first |

The agent restored all four before finishing, and the files were verified
byte-correct afterwards; **none of these mutations reached the delivered
code**. The lasting harm was diagnostic: the stale `.pyc` left behind by the
mutated source (Change 4) made the restored source appear broken.

Two safeguards were applied rather than trusting the restoration:

1. Every file was re-read and behaviourally re-verified against its intended
   semantics.
2. **All four mutations were deliberately re-applied and the suite re-run.**
   Each now fails loudly (6, 16, 2 and 8 failures respectively), so the
   delivered tests demonstrably defend these decisions. Before this cycle's
   tests existed, the `fold()` mutation passed silently — that gap is now
   closed.

*Process note for later cycles: a subagent's report that "src is restored" is a
claim, not evidence. Re-verify the source and clear `__pycache__` before
trusting any test result that follows agent fan-out.*
