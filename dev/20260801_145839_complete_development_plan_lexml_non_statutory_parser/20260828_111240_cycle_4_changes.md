## 3. A change deliberately **not** made

**Capturing Word's `numFmt` on `StyledPara`.** `ListNode.ordered` would be
exact if ingestion read the list's numbering format from `numbering.xml`;
instead it is inferred from an explicit enumerator in the item text, and a
Word-autonumbered list therefore reports `ordered=False`.

Adding the field is a two-line change to `docx_reader.py`. It is not made
because `StyledPara.to_dict()` emits every non-`None` field, so the new field
would appear in **all 15 `styled` goldens** — a change to Cycle 1's delivered
output shape, which the cycle process classes as major. The signal is not
needed until Cycle 5 chooses between `<ol>` and `<ul>`, and Cycle 5 can pay for
it then, with the golden diff reviewed as its own decision rather than
smuggled in here.

Recorded as spec decision **D-4** and carried forward as an open item.

## 4. A bug found in this cycle's own code, recorded because of how it was found

The first `_list_node` implementation **dropped every nested list item**: it
built child lists into detached Python lists that were never grafted back, so
a three-level list came out with only its top-level items and the rest lost
silently.

No golden could have caught it. As amendment A-4.6 records, **no sample has a
contiguous multi-level Word list**, so the corpus never reaches the code path.
It was found by writing the synthetic fixture the spec's test plan called for
and checking `all_source_indices` against the input — which is the argument for
writing a fixture when the corpus cannot reach a rule, rather than deferring
the test until a document arrives that needs it.

The rewrite is recursive and clamps rather than drops in all three malformed
shapes the fixture exercises (leading deep item, orphan level, skipped level).
