## Change 1 — Offline harness uses a resolver, not an in-place `schemaLocation` rewrite

| Field | Content |
|---|---|
| **What changed** | Method prescribed by `docs/20260801_004745_…` §11 and echoed in plan §8 "Cycle 0". Implemented in `src/lexml_nonstat/validate/schema.py` (`OfflineResolver`). |
| **Before → after** | **Before:** loop over `lexml/*.xsd`, rewrite `schemaLocation` attributes, write files back to disk. **After:** an `lxml.etree.Resolver` maps the remote URLs onto vendored stubs at parse time; `lexml/` is opened read-only and stays byte-identical to upstream. |
| **Why** | The rewrite mutates the vendored schemas, destroying the upstream baseline needed to detect schema drift — which plan §10 lists as a tracked risk and Cycle 0's own exit criterion depends on. Raised with the user, who chose the resolver. |
| **Blast radius** | None on code (no prior code existed). Documentation only: §11's recipe is superseded. Adds `test_vendored_schemas_are_never_modified` as a standing guard. |
| **Plan impact** | Plan §8 "Cycle 0" amended (Amendment A-0.1). `docs/20260801_004745_…` §11 left as the historical investigation record, now superseded on this point — per the user's answer, the plan is the single source of truth. |
| **Severity** | **Minor** — changes how a not-yet-written component is built, not any delivered behaviour. Confirmed with the user regardless, since it diverges from a written recipe. |

## Change 2 — Three stubs required, not one

| Field | Content |
|---|---|
| **What changed** | `docs/20260801_004745_…` §11 and plan §8 state that offline compilation needs a vendored `xml.xsd`. It needs three stubs. |
| **Before → after** | **Before:** stub `http://www.w3.org/2001/xml.xsd` only. **After:** also stub `…/mathml2/common/xlink-href.xsd` and `…/mathml2/mathml2.xsd`, all three registered in `STUB_MAP`. |
| **Why** | `lexml-base.xsd` carries all three imports and libxml2 fetches every one. Verified by instrumenting the resolver: with only `xml.xsd` stubbed, the xlink import is requested over the network and compilation fails once it is refused. §11's recipe passed only because the investigation machine had internet — it would fail offline, defeating the cycle's purpose. |
| **Blast radius** | None on code. Corrects a documented procedure that would have failed on any offline machine or CI runner without egress. |
| **Plan impact** | Amendment A-0.1. |
| **Severity** | **Minor** — a correction to an unimplemented procedure. It is, however, the most consequential finding of the cycle: uncorrected, Cycle 0's central guarantee would have been false. |

## Note — hardening added during implementation (no prior behaviour affected)

Not a change to an existing feature, recorded because it shaped the delivered API.

A missing stub file was found to be **silently masked**: libxml2 answers an unreadable local `schemaLocation` by fetching the URL, so deleting a stub still compiled cleanly on this connected machine. Two candidate guards were tested and both proved ineffective — patching Python's `socket` (libxml2's HTTP is in C, below Python) and `XMLParser(no_network=True)` (does not reach the loader `XMLSchema()` uses for imports).

`OfflineResolver` therefore raises `MissingStubError` when a mapped stub is absent instead of declining. Mutation-verified: deleting `xlink-href.xsd` now takes the suite from 107 passing to 87 failing, where before the change it stayed entirely green.
