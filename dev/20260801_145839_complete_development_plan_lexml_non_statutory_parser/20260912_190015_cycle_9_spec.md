## 2. Reconciliation — what the cycle text does not settle

Four load-bearing ambiguities. All four were put to the user; all four answers
are recorded here as binding.

### Q-1 — "Promote all goldens to `tests/regression/`"

**Asked because** a literal reading is a `git mv` of 143 tracked data files and
11 test modules, rewriting `GOLDEN_ROOT` and every golden test's paths, for a
diff that moves **zero** behaviour — while §9.1's own layer table lists *Golden*
and *Round-trip / Cross-emitter / Conservation* as **separate layers**, which
the move would collapse.

**Answer: keep `tests/golden/`; amend the plan.** The goldens are already
consolidated in every sense the cycle cares about — one documented regeneration
command, byte-stable, and each kind's module re-checks validity and id
uniqueness *against the committed files* rather than against a fresh render. A
mass relocation is the unreviewable diff §9.4 exists to forbid. This follows the
**A-7.1 precedent** (a naming divergence recorded as an amendment rather than
absorbed) and the **A-8.1 precedent** (a bullet discharged by assertion when the
thing it asks for already exists).

Recorded as **A-9.1**. Cycle 9 therefore spends its effort on the regression
assertions that are genuinely *missing*, not on moving files that pass.

### Q-2 — the coverage gate's denominator

**Asked because** "≥85% on `hierarchy/`, `routing/`, `render/`" does not say
whether it is measured per package, per file, or in aggregate — and the answer
decides whether this deliverable is a formality (92% today) or a demand to test
two superseded debug scripts.

**Answer: per-package aggregate, with the debug `__main__.py` modules omitted
from the denominator**, the omission declared in `pyproject.toml` where it is
visible and reviewable.

Recorded as **A-9.2**. The gate then measures the logic the invariants depend
on, and cannot be quietly satisfied — or quietly broken — by a debug view.

### Q-3 — "batch mode for the 300+ corpus"

**Asked because** `parse` and `decisions-report` already accept `nargs="+"`,
already isolate per-document failures, and are already tested over all 15
samples in one invocation (`test_the_whole_corpus_in_one_invocation`,
`test_decisions_report_over_the_whole_corpus`). Taken narrowly the bullet is
already discharged.

**Answer: build a real `corpus` command.** It walks a **directory**, isolates
per-document failures so one bad file among 300 never aborts the run, and emits
**one aggregate report** reconciling routes, blockers, warnings, referee
decisions and citation resolution across the whole corpus — text and JSON.

Recorded as **A-9.3**. This is what the 15-sample corpus cannot already do, and
it is the instrument §10's top risk ("15 samples ⇏ 300+ corpus") names.

### Q-4 — `make regression`

**Asked because** there is no `Makefile`, and `python3 -m pytest tests/ -q` is
what `CLAUDE.md`, the README and `STATUS.md` all document.

**Answer: add a thin `Makefile`** whose targets wrap the existing documented
commands **verbatim**, adding no logic — plus a test asserting each recipe
matches the documented command, so the two cannot drift.

Recorded as **A-9.4**. A Makefile that owned its own recipes would be a second
source of truth for how to run the suite; one that delegates is a table of
contents.

### Non-blocking decisions taken without asking

| # | Decision |
|---|---|
| N-1 | **The mutation test is committed code, not a sweep.** Every prior cycle ran a throwaway sweep; the plan asks for "a deliberate mutation fails the suite" as a *test*. So the mutation harness ships in `tests/regression/` and re-runs forever. No new dependency (`mutmut` is not installed and would bring a second test runner). |
| N-2 | Mutations are applied **in-process, to a copy**, via `monkeypatch`/AST rewriting of the module under test — never by editing a source file on disk. A mutation harness that writes to `src/` and crashes leaves the tree corrupt; Cycle 2's incident record is the precedent for taking that seriously. |
| N-3 | The corpus report's data model is a **new frozen dataclass** that *embeds* `DecisionsReport` rather than re-deriving its counts. §7.4's identities are already checked by `DecisionsReport.check()`; a second implementation would be a second source of truth. |
| N-4 | `corpus` gets its own subcommand rather than a `--batch` flag on `parse`, so no delivered command's behaviour changes. |
| N-5 | The corpus-expansion guide and the `docs/`/`dev/` conventions are **one document** in `docs/`, linked from the README — they are the same audience asking the same question ("how do I add to this?"). |
| N-6 | Coverage runs as an **explicit command** (`make coverage`), not in `addopts`. A gate inside the default run would make every ordinary `pytest` invocation slower and would couple the suite to an optional dependency the bare checkout may not have. |

### G-3 `corpus` subcommand (A-9.3)

```
lexml-nonstat corpus [PATHS...] [--out DIR] [--format=text|json]
                     [--emitter=...] [--schema=...] [--generation=...]
                     [--profile=...] [--referee=...] [--linker=...]
                     [--limit=N] [--continue-on-error/--stop-on-error]
```

- A `PATH` that is a **directory** is walked for every supported suffix
  (`.docx`, `.html`, `.htm`, `.txt`), sorted, deterministic. A file is taken as
  itself. Default when no path is given: `samples/`.
- **Per-document isolation**: any exception from any one document is caught,
  recorded against that document, and the run continues. `--stop-on-error`
  opts out.
- Emits one `CorpusReport`, never per-document XML (that is `parse`'s job).

New module `src/lexml_nonstat/corpus.py`:

```python
@dataclass(frozen=True)
class DocumentOutcome:
    source: str
    ok: bool
    urn: str = ""
    profile: str = ""
    route: str = ""
    emitter: str = ""
    confidence: float = 0.0
    flat: bool = True
    documents: int = 0
    valid: bool | None = None          # None when validation was not run
    blockers: tuple[str, ...] = ()
    warnings: tuple[str, ...] = ()
    references: int = 0
    error: str = ""

@dataclass(frozen=True)
class CorpusReport:
    outcomes: tuple[DocumentOutcome, ...] = ()
    decisions: DecisionsReport = DecisionsReport()   # N-3: embedded, not re-derived
    @property
    def total(self) -> int: ...
    @property
    def succeeded(self) -> int: ...
    @property
    def failed(self) -> int: ...
    def by_route(self) -> tuple[tuple[str, int], ...]: ...
    def by_profile(self) -> tuple[tuple[str, int], ...]: ...
    def by_emitter(self) -> tuple[tuple[str, int], ...]: ...
    def by_blocker(self) -> tuple[tuple[str, int], ...]: ...
    def by_warning(self) -> tuple[tuple[str, int], ...]: ...
    def check(self) -> str | None:      # reconciliation, see below
    def to_dict(self) -> dict[str, Any]: ...

def walk_corpus(paths, *, limit=None) -> tuple[Path, ...]: ...
def run_corpus(paths, *, ...) -> CorpusReport: ...
def render_corpus_report(report: CorpusReport) -> str: ...
```

**"Reconciling" is a checkable property, not a word.** `CorpusReport.check()`
returns the first failing identity or `None`:

1. `succeeded + failed == total`
2. every route in `by_route()` is in `EMITTERS`; every blocker code in
   `BLOCKER_CODES`; every warning code in `WARNING_CODES`
3. the route tallies sum to `succeeded`
4. the embedded `DecisionsReport.check()` passes (§7.4's identities)
5. a document that failed carries a non-empty `error` and no route; one that
   succeeded carries a route and an empty `error`

All ordering is count-descending then name, matching `ranked()` in
`telemetry/report.py`, so the report is deterministic (invariant #4).

### G-4 Committed mutation harness (N-1, N-2)

`tests/regression/test_mutation_bites.py` + a small in-process harness. A
**mutation** is a named, reversible patch to one delivered behaviour; the test
asserts the suite's own assertions **fail** under it. Each mutation names the
invariant it attacks and the test module expected to catch it.

Minimum set, with A-R.9's three named explicitly:

| # | Mutation | Attacks | Expected catcher |
|---|---|---|---|
| M-1 | Emit own prose **before** child sections in the nested emitter | **§5.4 Constraint 1** | nested validity + cross-emitter order |
| M-2 | Drop the `<Bloco nome="vazio"/>` filler | **§5.4 Constraint 2** | nested validity |

> **Correction, made during implementation (measured).** M-2 as worded above is
> **insufficient**: dropping the `vazio` filler *alone* does not violate
> Constraint 2, because `ORDER_BLOCO` is appended to every section
> unconditionally (A-5b.1/A-5b.2) and keeps satisfying the `minOccurs="1"`
> extension choice by itself. Measured on the carrier document: dropping
> `vazio` alone leaves **0** bare sections; stripping **every** `Bloco` from
> subsections-only sections leaves **5**, which the proposed schemas reject.
> The implemented mutation strips every `Bloco` and is therefore strictly
> stronger than the wording it replaces. Had it been implemented literally, it
> would have left valid output and been reported as a **surviving** mutation —
> a false gap in the suite.
| M-3 | Emit a prose leaf as a bare `<p>` with no `Agrupamento` wrapper | **§5.4 Constraint 3** | nested validity |
| M-4 | Drop the last block from a rendered section | conservation (#2) | `test_conservation_generico` |
| M-5 | Duplicate a leaf's text | no duplication (Rule B, #7) | conservation |
| M-6 | Reuse an `id` | id uniqueness (#5) | golden + bundle uniqueness |
| M-7 | Skip a level in the flat id path | ancestor totality (Rule A, #6) | flat reversibility |
| M-8 | Let a referee override a high-confidence rule | referee advisory (#9) | routing/attack tests |
| M-9 | Make `ORDER_BLOCO` ordinals non-monotonic | order recoverability (A-5b.2/A-7.5) | three-way oracle |
| M-10 | Return the input unchanged from the linker's span harvest | linked invariants | linked goldens |

**M-1..M-3 are gated on `requires_nested`** — they assert *invalidity against
the proposed schemas*, which a bare checkout cannot judge. The harness itself,
and M-4..M-10, run unconditionally.

A mutation that **survives** is a test-suite gap and fails
`test_every_mutation_is_caught` with the mutation's own name — the harness
reports which invariant is unguarded, rather than only that something is wrong.

### G-5 Bare-checkout and no-network gates (A-R.9)

## 7. Risks

| Risk | Mitigation |
|---|---|
| **The mutation harness corrupts `src/`** — the single most dangerous thing this cycle builds | N-2: in-process patching only, never a file write; `test_no_mutation_leaks` proves it; `git status` checked before the report |
| A mutation **survives**, revealing a real test gap late in the cycle | That is the harness working. Treated as a finding to report, and either the guard is strengthened (minor) or the gap is recorded as an open item — never by deleting the mutation |
| `corpus` duplicating `parse`'s logic becomes a second source of truth | `corpus` calls `build_model` and the same renderers; `test_route_tallies_match_the_library` and `test_decisions_reconcile_with_decisions_report` pin it to the library and to the existing command |
| The coverage gate passing today makes it decorative | It gates *logic* modules only (A-9.2) and the floor itself is asserted, so lowering it is a visible diff |
| Subagents editing files they do not own | Disjoint ownership declared per item in §4; the leak test and a full-suite re-run by me, not by them |
| A new dependency creeping in | `pytest-cov` was already declared in `dev` extras; nothing else is added |
