## 1. Summary

All 15 samples are now divided into front matter, a primary body, back matter
and annexes, as spans of source-block indices, and both renderings of that
division validate against **both** schemas. `pytest` reports **1681 passed, 0
failed**: Cycles 0–2's 788 unchanged plus **893 new**.

The cycle's most consequential output is again a correction to the plan, and
this one changes the shape of the deliverable. Plan §8's Cycle 3 test list ends
with "`ParteInicial`/`ParteFinal` fragments validate on both schemas". A schema
probe run before any code was written shows that bullet cannot be the whole
story: `ParteInicial` and `ParteFinal` are declared inside
`HierarchicalStructure` only, and both schemas reject them inside
`DocumentoGenerico` — where, by plan §4.4, **14 of the 15 samples live**. A
single rendering would have served either one sample or fourteen, never both.
Cycle 3 therefore delivers a rendering-agnostic model plus two probe-verified
renderings (amendment A-3.1), which is §3.1's design working as intended: the
division is decided once, the rendering twice.

The second finding is the one that would have corrupted output. Applied
ungated to the corpus, a `^ANEXO` rule fires twice: correctly on
`port_mf_277`'s `ANEXO ÚNICO`, and catastrophically on `sumula_stj_125` block
369 — a bare paragraph reading `ANEXO` inside a compilation of court
precedents that has no annex, where it would amputate 28 blocks into a sibling
document that does not exist. This is amendment A-2.2's reasoning arriving a
second time, and it is resolved the same way: allowlist per profile (A-3.3).

A third result is quieter but is what makes the cycle safe to build on. Front,
body, back and annexes form a **partition** of every document's blocks — every
non-empty block in exactly one part, none twice and none nowhere. That is
plan §9.2's text conservation stated as arithmetic rather than as string
comparison, and it is asserted for all 15 samples.

### Do the tests bite?

Five mutations, each applied then reverted:

| Mutation | Result |
|---|---|
| Reported-judgment-date veto removed | **5 failed** |
| `find_epigraph` stops trusting Cycle 2's `None` | **54 failed** |
| No-ementa portal-artifact rule removed | **10 failed** |
| Annex qualifier requirement relaxed to bare `^anexo` | **1 failed** |
| **A-3.3 gate reversed** (`jurisprudencia_generico` given `annex_res`) | **4 failed** |

Restored: `1681 passed`.

**One mutation initially passed silently, and closing that gap changed the
code.** Deleting the profile gate's early return in `find_annexes` broke no
test. Investigating showed why, and the answer is worth recording: the corpus's
only stray marker is a *bare* `ANEXO`, which the qualifier requirement in the
pattern rejects independently of the gate — so the gate was defended only
indirectly, exactly how a load-bearing rule quietly becomes dead code. Two
things followed:

1. A new test, `test_profile_gate_is_load_bearing_on_its_own`, uses a
   *qualified* stray marker (`ANEXO I` in a synthetic súmula) to separate the
   two defences. Only the gate can reject that, and reversing A-3.3 now fails
   4 tests.
2. The early return in `find_annexes` turned out to be a **redundant fast
   path**, not the gate — `_is_marker` already returns `False` against an
   empty pattern tuple. It is now commented as such, so the next reader does
   not mistake it for the mechanism.

The corpus is therefore protected twice over, and both defences are now
asserted separately.

  `len(MATRIX) == PLAN_ROW_COUNT == 16`. The findings are pinned in this

  both schemas. The A-3.2 constraint is real and load-bearing for this cycle's
