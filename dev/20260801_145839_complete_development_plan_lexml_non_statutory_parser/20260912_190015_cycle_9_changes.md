## Changes to the spec, made during implementation

### s-1 — M-2's wording was insufficient; the implementation is stronger

The spec's M-2 read "drop the `<Bloco nome="vazio"/>` filler". **Measured
during implementation: that alone does not violate Constraint 2**, because
`ORDER_BLOCO` is appended to every section unconditionally (A-5b.1/A-5b.2) and
keeps satisfying the `minOccurs="1"` extension choice on its own.

On the carrier document: dropping `vazio` alone leaves **0** bare sections;
stripping **every** `Bloco` from subsections-only sections leaves **5**, which
`lexml-proposed/` rejects.

Implemented as the stronger form, with the measurement recorded in the test.
Had it been implemented literally, it would have produced valid output and been
reported as a **surviving mutation** — a false gap in the suite. The spec
carries the correction inline.

## Findings that are traps for future work

Four discoveries from the mutation harness, each a defect in the *harness's own
first draft* rather than in delivered code, and each a trap worth recording:

| # | Finding |
|---|---|
| f-1 | **`lexml_nonstat.referee.adjudicate` resolves to the *function*, not the module** — `referee/__init__.py` shadows the submodule. Patching it raises `AttributeError`, which a naive harness reports as *caught*: M-8 would have looked defended while never running. Resolved with `importlib.import_module` |
| f-2 | **Patching `render.common` does not reach the emitters** — `generico.py` binds `agrupamento`/`leaf_texts` at import time, so M-4/5/6/7 patched at `common` mutated nothing and reported as *surviving*. They must be patched at `render.generico` |
| f-3 | **M-2's wording** (s-1 above) |
| f-4 | **`_spans_of` is unreachable under `--linker=fixtures`** — the cache returns before `_parse_reply`, so it runs **zero** times corpus-wide. M-10 patches `find_refs`, the seam actually on the fixture path |

f-1 and f-2 share a shape worth naming: **a mutation that fails to apply looks
exactly like a mutation the suite caught.** The harness therefore records *how*
each mutation was caught (`MutationResult.how`) and distinguishes an
`AssertionError` — the project's own assertion firing — from an incidental
crash, so "caught by accident" is visible rather than banked.
