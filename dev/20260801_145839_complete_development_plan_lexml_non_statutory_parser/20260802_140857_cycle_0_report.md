## 1. Summary

The parser now has a package skeleton and a dual-schema validation harness that compiles `lexml-br-rigido.xsd` and `lexml09-flexivel.xsd` **without network access** and **without modifying the vendored schemas**. The investigation's §2.1 encoding matrix — the empirical basis for the entire design — is now an executable, parametrised test running every row against both schemas, so a schema revision that invalidates a design assumption fails a test that names it. `pytest` reports **107 passed, 0 failed**.

The cycle also corrected a defect in the planning documents. The prescribed offline recipe (`docs/20260801_004745_…` §11) stubbed one of three remote imports and would have **failed on any machine without internet** — precisely the guarantee Cycle 0 exists to establish. It appeared to work only because the investigation ran on a connected machine. Corrected, verified by mutation, and recorded as plan Amendment A-0.1.

## 5. Changes to existing features

**None.** This is the first cycle: no source tree, no test suite, no prior behaviour, API, output shape, or test existed to change. Nothing was weakened, renamed, or deleted.

Full detail in `20260802_140857_cycle_0_changes.md`. Two entries there record divergences from the **planning documents** (not from delivered code), both raised with the user and agreed before implementation, and neither contradicting a ratified decision in plan §0:

1. **Resolver instead of in-place `schemaLocation` rewrite** — keeps `lexml/` byte-identical to upstream so schema drift stays visible. *User chose this option.*
2. **Three stubs, not one** — the documented recipe was incomplete and would fail offline.

Both classified **minor** (they change how an unwritten component is built, not delivered behaviour) but were confirmed with the user anyway, since they diverge from a written procedure.

### Hardening added during implementation

A missing stub turned out to be **silently masked**: libxml2 answers an unreadable local `schemaLocation` by fetching the URL over the network. Two plausible guards were tested and **both failed**:

| Attempted control | Outcome |
|---|---|
| Patch Python's `socket` to refuse all connections | compiled anyway — libxml2's HTTP is in C, below Python |
| `etree.XMLParser(no_network=True)` | compiled anyway — does not reach the loader `XMLSchema()` uses for imports |

`OfflineResolver` now raises `MissingStubError` when a mapped stub is absent, rather than declining and letting libxml2 fall back. This is why the mutation test in §3 bites.
