### C-2 — `TxtReadError` introduced as a `DocxReadError` **subclass**

| Field | Content |
|---|---|
| **What changed** | `src/lexml_nonstat/ingest/txt_reader.py` — new `TxtReadError(DocxReadError)`; the reader's four `raise` sites use it |
| **Before → after** | A missing `.txt` raised `DocxReadError("no such file: report.txt")` — a *DOCX* error about a text file → it raises `TxtReadError` with the same message shape |
| **Why** | Found by `test_missing_file_raises`. The reader as first delivered reused `DocxReadError` and documented the reuse; the message a user sees said DOCX about a `.txt`, which is simply wrong |
| **Blast radius** | **Zero.** A *subclass*, deliberately, so every pre-existing `except DocxReadError` — four `__main__` modules and `cli.py` — keeps catching it. Asserted by `test_txt_read_error_is_catchable_as_a_docx_read_error` |
| **Plan impact** | None |

This is the opposite choice from `HtmlReadError`, which is a *sibling*, and the
asymmetry is deliberate: HTML failures come from a different library and a
caller should not conflate them silently, while a text file has the one failure
mode `DocxReadError` already means.

## Defects found and fixed in this cycle's own code

Four, all found by this cycle's tests or its own smoke-testing, all in code
written during this cycle.

| # | Defect | Found by | Fix |
|---|---|---|---|
| **D-1** | `--emitter=generico-aninhado` validated its output against the **shipped** schemas, reporting 35 errors that were the schema's absence rather than the document's defect | CLI smoke test | `_generation_for(emitter, requested)` — the generation an emitter's output is validated against is a property of the emitter (A-5b.3), not a free choice |
| **D-2** | An **undeclared UTF-8** HTML file was decoded as latin-1, turning `SEÇÃO` into `SEÃÃO` — mojibake that then flowed through NFC normalisation into the XML looking like a source that really said that | CLI smoke test on a hand-written fixture | `_decode` defaults to UTF-8 when the document declares nothing; a declaration still wins |
| **D-3** | The first repair (`HTMLParser(encoding="utf-8")`) **overrode** a correct latin-1 declaration and raised `UnicodeDecodeError` lazily from `element.text` deep inside the walk — breaking the reader's "never raises on content" contract | Encoding matrix across five declaration/encoding combinations | Decode up front; latin-1 is the last candidate because it maps every byte, so the decision cannot fail |
| **D-4** | An **XML declaration** on an HTML document made lxml return an *empty tree* — silent, total text loss that nothing downstream could detect | Encoding matrix | Strip a leading XML declaration before parsing; its encoding was already read off the bytes |

D-2/D-3/D-4 are one finding in three parts, and the shape is worth recording:
**an encoding bug is invisible to every invariant the plan has.** Conservation
compares the source text to the emitted text, and both sides were mojibake, so
they matched. Only reading the output found it.

Three exit-code defects were also found and fixed during smoke-testing: an
unsupported suffix and a directory both exited 1 (a document failure) rather
than 2 (a misuse), a directory was misdiagnosed as "unsupported format
'.tmpdir'", and an unknown profile printed its error twice in two different
orders. All three are in `cli.py`, written this cycle.

## Changes considered and **rejected**

### R-1 — Making the nested emitter render rather than refuse (**rejected — the plan is explicit**)

When the suite was first run without `lexml-proposed/`, **32 tests failed**,
all because `--emitter=generico-aninhado` exits 2 when the capability is
absent. The tempting reading is that A-5b.3 ("the renderer always renders")
makes the refusal wrong.

It does not. Plan **§5.2** is explicit, and distinguishes exactly this:

> Selected by `--emitter=generico-aninhado`; **emitter selection** refuses with
> the probe's diagnostic when the vendored schemas are flat — the renderer
> itself always renders, see **A-5b.3**.

The renderer is the function; selection is the CLI. A-R.9 asks for precisely
this refusal. **The defect was in the new tests**, which assumed the CLI would
render nested markup unconditionally; they are now gated on `requires_nested`
like every other nested assertion, and a new ungated test
(`test_nested_selection_is_answered_one_way_or_the_other`) asserts the *clean*
answer in **both** configurations — which is what makes A-R.9's "exits cleanly
with the probe's diagnostic" checkable on the bare checkout it most concerns.

### R-2 — Registering a second `generic` profile (**rejected — already delivered**)

Cycle 8's deliverable list names "`generic` catch-all profile". It landed in
**Cycle 2** and was extended in Cycle 3 (A-3.3). Building a second would give
`select_profile` two weak claimants and make its answer depend on registration
order. Discharged by assertion instead —
`test_the_generic_catch_all_profile_is_registered` pins that it exists, that its
`base_score` is above zero, and that no other profile's is higher. Recorded as
amendment **A-8.1**.

### R-3 — Building `validate/rules.py` (**rejected — no rule is homeless**)

§3's layout names it. Every check it would hold already has an owner:
`render_norma_checked`'s four gates, `render/ids.py`'s Rule A, the conservation
comparison, `probe_capabilities`. A module re-implementing them would be a
second source of truth — the failure Cycle 4b's report warns about for routing.
Recorded in the plan as part of **A-8.2** rather than silently skipped.

### R-4 — Making the per-package `__main__` modules thin wrappers over `cli.py` (**rejected as major**)

Offered as an option and declined by the user (R-7). It would remove duplicated
formatting but change the delivered stdout of seven commands, three of which
have golden-backed tests. The CLI delegates to the same library functions
instead, so `dump-tree` and `hierarchy/__main__` agree by construction.

### R-5 — Normalising the written filename to the source stem (**rejected**)

`parse -o` names files from a slug of the URN
(`urn_lex_br_ministerio.fazenda_portaria_2018-06-07_277.xml`), which is long.
Using `port_mf_277_20180607.xml` would read better — and would make two
documents with different URNs collide whenever their filenames matched, which
is exactly the situation the 300+ corpus will produce. The URN is the identity;
the filename follows it. §2.9's `!anexo1` convention is preserved verbatim.

### R-6 — Renaming `lexml_nonstat.warnings` to avoid shadowing the builtin (**rejected**)

`Warning` shadows the builtin inside one module. Considered `CliWarning` and
`Diagnostic`; both say less about what the thing is, and the module is never
`import *`-ed. The risk is pinned instead: `test_warning_is_not_an_exception`
asserts it is not a `BaseException` subclass and is not `builtins.Warning`, so a
later `except Warning:` meaning the builtin is a type error rather than a
handler that silently never matches.
