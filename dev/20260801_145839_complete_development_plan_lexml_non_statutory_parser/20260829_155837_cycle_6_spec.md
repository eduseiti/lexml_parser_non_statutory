## 2. Reconciliation outcomes

Six schema facts were **measured before writing anything** (33 probe cases
against both shipped schemas, plus `lexml-proposed/`), following the Cycle 5b
precedent. Four contradicted the plan and were escalated; all six are recorded
here because the emitter is built against measurement, not against §4.3's
snippet.

### Q-1 — Dispositivo ids are pattern-constrained. *(asked; answer: separate allocator)*

`lexml09-flexivel.xsd` restricts `idArtigo` with an `xsd:pattern`:

```
art(\d+(-[0-9]{1,3}){0,3}|1u)((_cpt|(_(par|dpg)(\d+…|1u)))(_(inc|ali|dpg)\d+…)?)?
```

so `art1`, `art1_cpt`, `art1_par1`, `art1_cpt_inc1` are legal and
**`pp1_art1` is rejected by both schemas** (probe N5). Cycle 5's path-composed
`IdAllocator` therefore *cannot* issue dispositivo ids: the two id grammars are
incompatible.

**Decision:** a separate `DispositivoIds` allocator in `render/norma.py`.
`render/ids.py` is left untouched — its docstring ratifies the path scheme, and
mixing a second grammar into it would make one module answer to two
constraints. The two id spaces coexist in one document without collision,
because a `Norma` primary has no `Agrupamento`s at all and an annex has no
dispositivos. **Amendment A-6.1.**

### Q-2 — `ParteInicial`/`ParteFinal` are closed; A-5.1's region rendering is unavailable. *(asked; answer: fold front, fall back on back)*

Measured (probes B5, B13, B14): both elements are `xsd:sequence`s of *only*
their named parts. `<Agrupamento>` and bare `<p>` are **rejected inside both**.
So the `generico` route's "regions, not parts" rendering — A-5.1, which exists
because 40 non-empty blocks in 6 samples sit inside a hull and inside no named
part — has **no statutory equivalent**.

Two escapes exist, and only one is legal:

- `Preambulo` is `textoSimplesType`, so it takes **multiple `<p>`** (probe C1
  valid). Front residue folds in.
- `ParteFinal` has none: an extra `<p>` inside `Assinatura` is rejected (C2), a
  childless `AgrupamentoHierarquico` is rejected (C6), and `Agrupamento` is
  rejected outright (B5).

**Decision:** front residue is folded into `Preambulo` as extra `<p>`, in
document order, before the preamble's own lines. Back residue has no home, so a
document carrying it **fails conservation and falls back to `generico`** with
blocker `back_matter_residue`. Text is never dropped to keep a route.
`port_mf_277` has zero residue either way, so this changes nothing for the
corpus and everything for the 300 unseen documents. **Amendment A-6.2.**

### Q-3 — Cycle 4 models no articulation. *(asked; answer: Artigo + Caput + Paragrafo + Inciso)*

`port_mf_277`'s two articles are plain `Para`s in `body.preamble`;
`DocumentModel.articulacao` is empty. Cycle 6 must **build** the articulation.

**Decision:** build four levels — `Artigo`, `Caput`, `Paragrafo`, `Inciso` — all
four probed valid (N1, N9, N10). The corpus exercises only `Artigo`+`Caput`, so
`Paragrafo` and `Inciso` are tested by **synthetic fixtures**, the A-1.3 / A-4.6
precedent. `Alinea` and `Item` are deliberately **not** built: nothing in the
corpus reaches them and the same argument that rejected `nota_tecnica` in A-2.4
applies — an untested level is a shipped guess. A document needing them falls
back to `generico`, which is safe by construction.

Labels come **only** from `parse_label()`. No second grammar (Cycle 4's
standing rule, and A-3.4's).

### Q-4 — the validate-then-fallback gate. *(asked; answer: validity + conservation + coverage)*

§4.2 says "if it fails schema validation *or the conservation/coverage
invariants*". **Decision:** all three, each producing a named blocker:

| Gate | Blocker code | Vetoes |
|---|---|---|
| fails either shipped schema | `statutory_invalid` | yes |
| word multiset ≠ the `generico` render's | `statutory_lossy` | yes |
| articulation coverage < 0.6 | `low_coverage` (existing) | yes |
| back-matter residue with no legal home (Q-2) | `back_matter_residue` | yes |

A schema cannot detect lost text, so validity alone would let a *valid* document
silently drop a paragraph — which invariant #2 forbids. **Amendment A-6.3.**

### Q-5 — `render/anexo.py` vs Cycle 5's delivered annex code. *(asked; answer: extract and share)*

Cycle 5's A-5.6 already delivers the entire §2.9 convention. A second
implementation would be the "competing source of truth for a decision already
taken" that A-3.4 rejected.

**Decision:** `generico.py`'s private `_render_annex` moves to a public
`render/anexo.py`; `generico.py`, `generico_aninhado.py` and `norma.py` all call
it. **Output must be byte-identical** — the 16 committed `generico` goldens and
16 `generico_aninhado` goldens not moving is the regression that proves the
refactor is behaviour-preserving. Logged as a **minor** change (internal
refactor, no output change), and re-checked with `regen_goldens.py` reporting
`0 changed`.

### Q-6 — A-R.8, nested annex bodies. *(asked; answer: explicit flag, flat default)*

Probed: a nested annex body is valid on `lexml-proposed/` and correctly rejected
on `lexml/`. **Decision:** `render_anexo(model, annex, *, nested=False)`, chosen
by the emitter (`generico`/`norma` → flat, `generico-aninhado` → nested), never
by the capability probe. Output that changed depending on which directories
exist on the machine would break determinism (§9.2) and make goldens
un-committable. A-R.8 is discharged by tests proving the nested annex validates
on `lexml-proposed/`, skipping with the probe's diagnostic when absent (A-5b.3's
rule).

### Non-blocking decisions taken without asking

- **D-1** `Anexo` accepts `DocumentoGenerico` or `DocumentoArticulado`, never
  `Norma` (probe A3/B1). An annex is always `DocumentoGenerico` here, mirroring
  the reference parser's `isArticulatedAnexo` being false for `port_mf_277`.
- **D-2** `Anexos` must follow `ParteFinal` inside `Norma` (probe B2 fails when
  reversed). The emitter appends in schema order, not document order — the same
  rule Cycle 3 already applies inside `ParteInicial` (A-3.2's closing note).
- **D-3** `Caput` carries its own `Rotulo`, duplicating the `Artigo`'s. §4.3's
  snippet does it, the reference parser does it, and it is valid (N1); a `Caput`
  *without* one is also valid (N4), so this is convention, not necessity, and we
  follow the reference.
- **D-4** An `Artigo` **must** have a `Rotulo` and it must precede `Caput`
  (probes N3, N6 both fail). This is what makes the plan's "a deliberately
  mis-ordered tree fails validation" test assertable against the schema itself
  rather than against our own check.
- **D-5** `Artigo` label `único` maps to id `art1u` (probe N13 valid) — the
  pattern's own escape hatch, and `parse_label` already yields value `(1,)` for
  `único`.
- **D-6** Tables and lists are **rejected inside `Caput`** (probes B10, B11). A
  body article whose content includes a table or list cannot be articulated, so
  it triggers the `statutory_lossy` fallback rather than dropping the node.
- **D-7** New module `render/norma.py` owns `Articulacao` construction; the
  four dispositivo dataclasses live there rather than in `model/nodes.py`,
  because they are a *rendering* of the statutory route and `model/nodes.py`'s
  docstring ratifies its types as rendering-agnostic.

### 3.2 `src/lexml_nonstat/render/norma.py` (new)

```python
EMITTER = "norma"

@dataclass(frozen=True) class Dispositivo:      # base: rotulo, ident, paragraphs
@dataclass(frozen=True) class Inciso(Dispositivo)
@dataclass(frozen=True) class Caput(Dispositivo):   incisos: tuple[Inciso, ...] = ()
@dataclass(frozen=True) class Paragrafo(Dispositivo): incisos: tuple[Inciso, ...] = ()
@dataclass(frozen=True) class Artigo:
    rotulo: str; ident: str; caput: Caput; paragrafos: tuple[Paragrafo, ...] = ()

class DispositivoIds:                       # Q-1's schema-legal allocator
    def artigo(self, value: tuple[int, ...] | None, *, unico: bool = False) -> str
    def caput(self, artigo_id: str) -> str
    def paragrafo(self, artigo_id: str, n: int, *, unico: bool = False) -> str
    def inciso(self, parent_id: str, n: int) -> str

def build_articulacao(model: DocumentModel) -> tuple[Artigo, ...]
def render_articulacao(articulacao: tuple[Artigo, ...]) -> etree._Element | None
def render_norma(model: DocumentModel) -> RenderedDocument            # raw, no gate
def render_norma_checked(model, *, generico=None) -> tuple[RenderedDocument, tuple[Blocker, ...]]
def render_statutory(model: DocumentModel) -> RenderedDocument        # §4.2, with fallback
def render_norma_from_docx(path, *, filename=None) -> RenderedDocument
```

`render_statutory` is the public entry point: it renders `norma`, runs the
Q-4 gate, and returns either the statutory bundle or the `generico` fallback,
whose `RenderedDocument.emitter` then reads `"generico"` — so the artifact says
which emitter actually produced it. The reason is logged at `WARN` and recorded
as a `Blocker`.
