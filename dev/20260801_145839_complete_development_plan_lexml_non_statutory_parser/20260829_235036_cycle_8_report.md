## 1. Summary

The parser gained a face and a spine. `cli.py` puts eight subcommands over the
seven cycles of library beneath it, reading DOCX, HTML and plain text through
one dispatching front door, and reporting what it concluded through a
structured warning channel with a closed code list. The claim Cycle 8 actually
owed — *"handles any document"* — is discharged by ten degenerate documents that
each traverse the whole pipeline and emit XML valid on **both** schemas, and by
six malformed inputs that are each refused in one line with a non-zero exit and
no traceback.

**5250 passed, 0 failed, 4 skipped**, up from a 4725-pass baseline: **525 new
tests**, no prior test modified. All **135 goldens across 9 kinds are
byte-identical** — this cycle changed no delivered behaviour. A 25-mutation
sweep over the new code killed 25 of 25.

Two findings are worth the reader's time. First, **§5.2's refusal is correct
and the tests were wrong**: 32 tests failed on a checkout without
`lexml-proposed/`, and the tempting reading was that A-5b.3's "the renderer
always renders" made the CLI's refusal a defect — but §5.2 separates *emitter
selection* from the *renderer*, and A-R.9 asks for exactly that refusal.
Second, and more uncomfortable: **an encoding bug is invisible to every
invariant this plan has.** An undeclared UTF-8 HTML file read `SEÇÃO` as
`SEÃÃO`, and conservation compared mojibake to mojibake and matched. Only
reading the output found it.


`HtmlReadError` is a **sibling** of `DocxReadError` and `TxtReadError` is a
**subclass**, and the asymmetry is deliberate: HTML failures come from a
different library and a caller should not conflate them silently, while a text
file has exactly the one failure mode `DocxReadError` already means — so every
pre-existing `except DocxReadError` keeps working, asserted directly.

## 7. Deviations and open items

- **The `generic` profile bullet was discharged by assertion** rather than new
  code (A-8.1). Nothing is owed.
- **`validate/rules.py` is not built** (A-8.2), deliberately. Nothing depends
  on it.
- **HTML/TXT are tested by synthetic fixtures**, per the A-1.3 / A-4.6
  precedent, because the corpus has no such sample. If real HTML exports of the
  300+ corpus appear, the mapping table in `html_reader.py` is where they
  should be checked first — particularly the `margin-left` → twips conversion,
  which is the one number a real export could contradict.
- **`empty` and `whitespace_only` emit a bare `<DocumentoGenerico/>`** with no
  `PartePrincipal`. Valid on both schemas, so E-3 holds, and the
  `empty_document` warning reports it. Left as-is: the alternative — an empty
  `PartePrincipal` — would be fabricating a container for content that does not
  exist. Recorded here so Cycle 9 can revisit it if a consumer objects.
- **`deeply_nested_lists`' six levels do not become six groupings** in the flat
  emitter. Expected for `generico`; it is the fixture Cycle 9 should point at
  the nested emitter if it wants a depth-preservation assertion.
