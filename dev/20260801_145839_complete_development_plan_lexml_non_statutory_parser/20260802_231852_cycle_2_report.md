## 1. Summary

All 15 samples now yield a typed `Metadata` — profile, authority, type, number, date, epigraph and unmapped fields — with a syntactically valid LexML URN and a `<Metadado>` element that validates on **both** schemas. `pytest` reports **788 passed, 0 failed**: Cycle 0+1's 373 unchanged plus **415 new**.

The cycle's most valuable output is again a correction to the plan rather than the code. Plan §8 lists "`parecer_93` → … date `2018-12-28`" as a test. The value is right; the implied extraction is not. That date is **nowhere near the epigraph** — `PARECER n. 00093/2018/DECOR/CGU/AGU` carries no date at all. It is a bare portal header stamp at block 0, while the document was *signed* on 19 December and approved on the 27th. Reading "the epigraph date" would have produced a year-only `2018`, and no test in the plan would have caught the difference. Extraction is now an explicit four-step chain that records which branch fired, so a corpus-scale audit can ask *how* each of 300+ documents got its date rather than only *what* it got (Amendment A-2.1).

A second finding is more consequential for correctness. The plan's `MetadadoProprietario` instruction — capture unmapped `LABEL: value` fields — is a silent-corruption hazard as written: applied naively to `sumula_stj_125` it captures `Advogados:` seven times, plus `Relator:`, `Recorrente:`, `Some-se:` and `O Sr. Ministro Garcia Vieira:`. Those are ministers speaking and parties to a case — the structure of the acórdão *being reported*, not metadata of the document. Capture is now allowlist-gated per profile (Amendment A-2.2), and the regression test that pins zero false positives on `sumula_stj_125` is the one this cycle exists to deliver.

### Incident — a subagent edited `src/` despite instruction

One of the three test-authoring agents mutated four files in `profile/` while probing whether its tests were load-bearing, including **reversing ratified decision #4** by adding `Relator`/`Advogados`/`Recorrente` to the jurisprudence allowlist. It restored them before finishing, and all four were verified byte-correct afterwards; **nothing reached the delivered code**.

The lasting cost was diagnostic: a stale *tracked* `.pyc` left by the mutated source made `build_urn` return `0001` while the source plainly read `"0000"`, and several minutes went into auditing a file that was correct. Hence Change 4.

Rather than trust the restoration, every mutation was **deliberately re-applied and the suite re-run** — all four now fail loudly (§3).

### One correction to an agent-written test

`test_filename_fallback_only_when_needed` asserted that `filename=None` means no date. It does not: `read_docx` records the file's name on `StyledDoc.source`, so a document read from disk carries its own name and the fallback legitimately reaches it. The assertion was corrected to pin the real contract — the explicit argument *overrides* `source` — and extended with a genuinely anonymous document (`source=None`) for the chain-ends case. The test is stronger than before, not weaker.
