## 2. Verification performed before specifying

Cycle 0's whole purpose is to make the investigation executable, so the investigation's claims were re-checked first rather than assumed.

**Finding 1 — §11's offline recipe is incomplete (load-bearing).** The investigation doc states that compiling offline requires stubbing `xml.xsd`. In fact `lexml-base.xsd` carries **three** remote imports:

| Import | Namespace | Stubbed by §11? |
|---|---|---|
| `http://www.w3.org/2001/xml.xsd` | `xml` | yes |
| `http://www.w3.org/Math/XMLSchema/mathml2/common/xlink-href.xsd` | `xlink` | **no** |
| `http://www.w3.org/Math/XMLSchema/mathml2/mathml2.xsd` | `MathML` | **no** |

Probing with a resolver that refuses remote URLs showed the xlink import **is** actually fetched (`REMOTE FETCH ATTEMPTED: …/xlink-href.xsd`, compile fails). §11 appeared to work only because this container has network access. On a genuinely offline machine it fails — precisely the condition Cycle 0 must guarantee. Verified fix: three stubs, after which both schemas compile with all remote resolution refused.

**Finding 2 — the §2.1 matrix reproduces exactly.** All 16 distinct rows were probed against both compiled schemas. Every result matched the plan, including all six negatives. The plan's structural findings are sound and are adopted unchanged as test expectations.

**Finding 3 — minimal referenced surface of the stubbed namespaces.** `lexml-base.xsd` references only `xlink:href` (attribute, lines 253/266) and `mathml:math` (element, line 807). Stubs need cover nothing more.

**Finding 4 — discovered during implementation: a missing stub is silently masked.** Deleting `xlink-href.xsd` and recompiling *succeeded*. libxml2 responds to an unreadable local `schemaLocation` by falling back to fetching the URL, so on any connected machine the offline guarantee can rot with no visible symptom, surfacing only for whoever first runs the suite without internet.

Two obvious controls were tried and **both proved ineffective**:

| Control | Result |
|---|---|
| Patch Python's `socket` to refuse connections | compiled anyway — libxml2 does its HTTP in C, below Python |
| `etree.XMLParser(no_network=True)` | compiled anyway — the flag does not reach the loader `XMLSchema()` uses for imports |

The effective fix is in `OfflineResolver` itself: a mapped stub whose file is absent raises `MissingStubError` rather than declining, so libxml2 is never given the chance to fall back. Verified by mutation — with a stub deleted the suite goes from 107 passing to **87 failing**, where previously it stayed fully green.

Correspondingly, the offline test asserts the set of URLs *our resolver served* equals `STUB_MAP`, rather than trying to prove a negative about network traffic.

## 3. Reconciliation outcomes

### Asked and answered

**Q1 — How should the offline harness avoid the network?**
The plan (and `docs/…004745` §11) prescribes rewriting `lexml/*.xsd` **in place**. Raised because it mutates the pristine vendored schemas and destroys the upstream baseline needed to spot schema drift.
**Answer: custom `lxml` resolver; schemas left byte-identical.** Remote import URLs are intercepted at parse time and mapped to vendored stubs. `lexml/` is never opened for writing.

**Q2 — How to record the §11 incompleteness (Finding 1)?**
**Answer: amend the plan document** with an Amendments entry correcting the Cycle 0 harness description from one stub to three, and record it in the cycle report. The plan remains the single source of truth.

**Q3 — Matrix test scope?**
**Answer: the full §2.1 matrix, every row, against both schemas.** The plan's exit criterion says exactly this.

### Decided without asking (non-blocking)

- **Stub fidelity.** Stubs declare only the referenced surface (§2, Finding 3); MathML content is `xs:any processContents="skip"`. Consequence — MathML formula *interiors* are not deeply validated. Irrelevant for this corpus (no MathML in the 15 samples; `Formula` is unused on the non-statutory route) and flagged to the user during reconciliation. Recorded here as a known, accepted limitation.
- **Stub location:** `src/lexml_nonstat/validate/stubs/` — ships with the package, unambiguously ours, never confusable with `lexml/`.
- **Package name:** `lexml_nonstat` under `src/` layout, per the plan's §3 tree.
- **Build backend:** `setuptools` (no preference stated; least surprising).
- **`httpx` / `saxonche`:** declared as *optional extras* (`referee`, `xslt`), not core deps — nothing in Cycle 0 needs them, and the regression suite must never require network.
- **Test file organisation:** `tests/unit/`, matching the plan's §9.1 table.

## 4. Expanded goals

### 4.1 `src/lexml_nonstat/validate/stubs/` — vendored offline stubs

Three files, each declaring only the surface `lexml-base.xsd` references:

| File | Target namespace | Declares |
|---|---|---|
| `xml.xsd` | `http://www.w3.org/XML/1998/namespace` | attributes `lang`, `space`, `base`, `id` |
| `xlink-href.xsd` | `http://www.w3.org/1999/xlink` | attributes `href`, `type`, `role`, `title`, `show`, `actuate` |
| `mathml2.xsd` | `http://www.w3.org/1998/Math/MathML` | element `math` (mixed, `xs:any`/`skip`) |

### 4.2 `src/lexml_nonstat/validate/schema.py` — the harness

```python
SCHEMA_NAMES: tuple[str, ...] = ("rigido", "flexivel")

class OfflineResolver(etree.Resolver):
    """Maps the three remote w3.org imports onto vendored stubs."""

def schema_dir() -> Path: ...
def stub_dir() -> Path: ...

def load_schema(name: Literal["rigido", "flexivel"]) -> etree.XMLSchema:
    """Compile one schema offline. Cached; raises UnknownSchemaError on a bad name."""

def load_schemas(selector: str = "both") -> dict[str, etree.XMLSchema]:
    """selector in {both, rigido, flexivel} -> ordered {name: compiled schema}."""

def validate(doc, selector: str = "both") -> ValidationReport:
    """Validate an element / ElementTree / bytes / str / Path against the selection."""
```

Behaviour requirements:

- Compilation is **cached** per schema name (compiling is the expensive step; every later cycle validates repeatedly).
- Compilation resolves **no** network URL. Any remote resolution attempt is a bug, and is asserted against in tests.
- `lexml/*.xsd` is opened **read-only**, never written.
- Accepts `str`, `bytes`, `Path`, `_Element`, or `_ElementTree`; a malformed document yields a report with a parse error rather than an exception escaping.

### 4.3 `ValidationReport` — per-schema results

```python
@dataclass(frozen=True)
class SchemaResult:
    schema: str                 # "rigido" | "flexivel"
    valid: bool
    errors: tuple[str, ...]     # formatted lxml error-log lines

@dataclass(frozen=True)
class ValidationReport:
    results: tuple[SchemaResult, ...]

    @property
    def ok(self) -> bool:       # True iff EVERY consulted schema passed
    def __bool__(self) -> bool: # == ok
    def errors_for(self, schema: str) -> tuple[str, ...]
    @property
    def failed(self) -> tuple[str, ...]
    def summary(self) -> str    # one line per schema, human-readable
```

The plan's wording is *"`ValidationReport.ok` iff both pass"*. Implemented as **every consulted schema passed**, so `--schema=rigido` yields `ok` on the single result — the natural generalisation, since a one-schema selection has no "both" to speak of.

### 4.4 `--schema=both|rigido|flexivel`

Cycle 8 owns the full CLI. Cycle 0 delivers the *selector plumbing* the flag needs, plus a minimal `python -m lexml_nonstat.validate` entry point so the flag is exercised end-to-end now:

```
python -m lexml_nonstat.validate --schema=both file.xml [file.xml ...]
```

Exit code `0` when all files validate under the selection, `1` otherwise; errors printed per schema. An invalid selector is a clean error, not a traceback.

Core: `lxml`, `python-docx`. Extras: `referee` → `httpx`; `xslt` → `saxonche`; `dev` → `pytest`, `pytest-cov`. Packaging: `src/` layout, package data includes `validate/stubs/*.xsd`. Pytest config: `testpaths=tests`, markers `live` (excluded by default per §9.3) and `slow`.

## 8. Risks

| Risk | Mitigation |
|---|---|
| Stub too thin → schema compiles but mis-validates | stubs cover exactly the referenced surface (Finding 3); the 16-row matrix would expose over-permissiveness |
| MathML interiors unvalidated | accepted and documented (§3); no MathML in corpus; revisit only if `Formula` is ever emitted |
| A test passes only because the machine has network | `test_compilation_makes_no_network_request` installs a refusing resolver and clears the cache first |
| lxml resolver ordering surprises | resolver registered on the parser used for the schema document; asserted by the no-network test |
| Later cycle mutates `lexml/` | `test_vendored_schemas_unmodified` fails loudly |
| Matrix drifts from the plan table | `test_matrix_covers_every_plan_row` pins the count |
